A linked import's control plane goes from its staging into the project as `.git` (W7.3, charter D12, I6). `stagedControlDirectory(staged)` names where the revisions authority writes it: on a root where a rename is a metadata operation, `importControlDirectory(operationId)` inside the import's staging directory, which `commitPendingProjectDirectory` moves into the project with one rename, before `tau.json` and never through the mutation pipeline; on a root where a rename copies (a picked folder, IndexedDB), the in-place project folder's own `.git`, so no pack is copied, and a discard or a sweep of the staging removes it with the import's other entries while the folder's owner marker names the import. `placeStagedControl` finishes a move a commit stopped partway through, file by file, keeping a file already moved only at its staged size, so a torn copy is moved again. On a moving root, a staging discarded after its commit moved `.git` and its files in but before `tau.json` leaves them in the folder; the pending create's journal row owns that staging, and its replay finishes the commit. `ImportSourcePin` takes the `linked` kind. A facts request may pass `measure: false` to be answered only from what the Project Index already holds and trusts, reading no file, and with it `recorded: 'import'` to be answered only with the facts a committed import's record seeded, each confirmed by a provider stat at exactly the recorded size and mtime, so a change the index has not observed yet is never answered with the record's ids. A recorded fact is trusted only once its file's mtime is more than the racy window (EQ7, 2 s) older than the record, so files placed within 2 s of the commit, which on a root that writes in place is most of them, are measured again by the caller rather than answered from the record.
