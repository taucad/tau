filesystem: minor

**Breaking:** `serveNodeFsProvider` (`@taucad/filesystem/backend/node`) returns the served owner, `NodeFsServer { run, close }`, instead of a bare disposer. Replace `await stop()` with `await server.close()`; `close` keeps the old disposer's behaviour and promise identity.

`run({ root, signal? }, async (scope) => …)` lets trusted in-process composition hold one admitted root's whole-root claim under the server's `NodeFsAuthorityHost`. The scope offers the rooted reads (`readFile`, `readdir`, `stat`, `exists`), the existing checked `writeFileChecked`/`deleteFileChecked`, and three new checked entry operations: `renameChecked` (one atomic native rename of a file or directory, with source, destination and directory-membership preconditions), `mkdirChecked` (one directory under an existing parent) and `rmdirChecked` (one empty directory). Conflicts are returned as `{ status: 'conflict', conflicts }`; nothing unchecked, no watch and no disposer is reachable from the scope. Every call re-decides `allowRoot`; calls in flight when the operation settles finish before the claim is released, and later calls reject `AUTHORITY_SCOPE_CLOSED`. `run` rejects `AUTHORITY_CLAIM_UNSUPPORTED` without an authority, `AUTHORITY_CLAIM_NESTED` from inside a live operation, and `AUTHORITY_HOST_INACTIVE` once `close` begins; `close` aborts open scopes' signals and waits for them. In-process checked replacement is not bound by the 8 MiB wire budget. New types: `NodeFsServer`, `NodeFsRootRun`, `NodeFsRootRunInput`, `NodeFsRootScope`, `CheckedRename`, `CheckedDirectory`, `CheckedEntryResult`, `CheckedEntryConflict`.

`ResourceQueue.queueForClaims` takes an optional `{ signal }` that withdraws a still-waiting operation with the signal's reason.

A mutation through the node provider is now refused with `ELOOP` when the path it actually resolves to classifies as granting less than the spelling the caller was classified on, not only when the real path is hidden. A write to `docs/chats` whose backing `docs` has become a symbolic link to `.tau` lands in the read-only records row `.tau/chats`, and is refused before anything changes. Reads keep the previous, narrower rule, so a consumer that reaches the control plane by its own name is unaffected.
