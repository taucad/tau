revisions: minor
---

One large-object rule on every leg, read from the tree and its parents as stock Git reads them: an entry whose bytes a parent holds keeps that parent's representation (a blob stays a blob, a pointer stays a pointer, and a merge keeps either side's), and new or changed content is stored as an LFS pointer exactly when the tree's own `.gitattributes` files say `filter=lfs` for it, with `[attr]` macros, the built-in `binary`, a bare or unset `filter`, and (natively) `core.ignoreCase` read as Git reads them. `cleanLargeObjects` takes the parents' blob ids (`largeObjectBasisOf(format, ...listings)`) and the case folding as options, and the native descriptor reports `ignoreCase`. `isTrackedLargeObjectPath` no longer tracks a path by its family alone. The families table and the 1 MiB threshold decide only which lines a cut adds to Tau's generated attributes block, and only when the tree already carries that block; the block is regenerated in place, and only in a cut that owes it a line, so a hand-written line after it still overrides it; its per-path lines escape glob characters, an older build's unescaped line is read as Git reads it and rewritten escaped in the cut whose new or changed content it names, and a block with no end marker is left alone. A tree with no Tau block gets nothing added and nothing written. `init` on both legs creates the setup files and never merges into one that exists: a brand-new project gets both, and a project an older build created (Tau's ignore block and no attributes file) gets its attributes file, so its unchanged parts stay pointers. Tau's derived-content ignores go in `.git/info/exclude` on both legs. Whether a repository is the person's is derived from disk on every open, so every session agrees, and a store Tau made gets its LFS filters configured on every open. The native port no longer refuses a repository that keeps large files on git LFS. It answers `readLargeObject` and `storeLargeObject` from the repository's own LFS store, and declares `keepsLargeObjectFiles`, so large-object adoption leaves a disk checkout's files whole.
