revisions: minor
---

One large-object rule on every leg, read from the tree as stock Git reads it: a path is stored as an LFS pointer exactly when the tree's own `.gitattributes` files say `filter=lfs` for it. `isTrackedLargeObjectPath` no longer tracks a path by its family alone. The families table and the 1 MiB threshold decide only which lines a cut adds to Tau's generated attributes block, and only when the tree already carries that block; the block is regenerated in place, so a hand-written line after it still overrides it. A tree with no Tau block gets nothing added and nothing written. `init` on both legs creates the setup files and never merges into one that exists: a brand-new project gets both, and a project an older build created (Tau's ignore block and no attributes file) gets its attributes file, so its unchanged parts stay pointers. Tau's derived-content ignores go in `.git/info/exclude` on both legs. The native port no longer refuses a repository that keeps large files on git LFS. It answers `readLargeObject` and `storeLargeObject` from the repository's own LFS store, and declares `keepsLargeObjectFiles`, so large-object adoption leaves a disk checkout's files whole.
