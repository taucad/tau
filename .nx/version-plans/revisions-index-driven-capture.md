A cut or comparison on a checkout whose filesystem has a Project Index starts from the last capture and reads only what the index changed and removed since (S10), on hosts without a complete change feed too. The checkout's memos keep the index's epoch, generation and the clock reading from before each capture. Each incremental capture runs the D5 compare first, so an edit no observer reported is found, re-reads what the compare holds as racy and every file whose timestamp was within the racy window of the last capture (EQ7), and asks the provider's modes again for the files it keeps (a mode change moves neither size nor timestamp); on a provider with no modes, a kept file whose mode differs from what a walk would give it walks everything. A `rescan` (a reload past the cursor, another epoch), no cursor, a memo-bypassing capture, changed ignored paths, or an index that fails to compare or answer walks everything, so an empty answer is never read as nothing changed and an index failure never fails the cut. A complete change feed still wins where it names the paths.
