Add a `sessionChanged` event for when the person signed in to a client changes, and the matching `sessionChanged` revision command on the host, which routes it to both `sync.machine` and `remote.machine` through the root. `sync.machine` (now version 7) reads the remote afresh under the new session without abandoning anything in flight: it unwatches and re-watches the remote's move stream (a stream refused under the last session is otherwise never re-read) and pulls as a remote move would, at once from an idle state or once a busy one settles (a conflict line's push included: its answer is recorded first); a manual remote that was busy pulls once it settles too. A project in `failed` opens again whatever the refusal, and so does one whose request made under the last session is answered with a refusal after the change, once any owed queue entry is recorded. A refusal of a push started after the change stays terminal. While quiescing the pull is held and made on release; a disconnect forgets it. `remote.machine` drops the stored-size figure the last session read and reads it again while connected; in every other state the event is declared ignored. A client no longer needs to close and reopen the root on a sign-in or sign-out.
