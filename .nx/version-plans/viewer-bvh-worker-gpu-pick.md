viewer: minor
---

`@taucad/viewer` builds a BVH larger than 32,000 triangles in a module worker on demand, instead of on the main thread when a pointer or section first needs it. The worker gets copies of the geometry's bytes and sends back the serialised tree, which the main thread deserialises without replacing the index. A worker error terminates the worker and retries once on a new one; a second error marks that geometry's tree failed, and no main-thread build runs in its place. The worker is terminated after a minute without work. Until a tree lands, a measurement or kinematics pick that needs it is pending rather than a miss, and is asked again when the tree lands. A section source waits for its tree, and becomes unsupported with the code `bvh-unavailable` when the build failed. Each build records a `renderer.bvh` span.

Model hover and click are answered from a GPU pick on both WebGL and WebGPU. A pass draws the pickable meshes into an ID and world-position target at CSS-pixel resolution, as the viewport draws them: transforms, visibility, layers, face side and the section clip. It runs only when its inputs changed and the camera has been still for 100 ms, and is read back asynchronously. `scene.raycast` answers synchronously from the read-back copy. While the copy does not show the scene as drawn, the pick is pending: the hover stays as it is, and a click is ignored rather than treated as a miss, so it does not clear the selection. When the pass lands, R3F `events.update()` runs once. Rays that do not leave the camera through a pixel, and renderers that cannot read the pass back, use the BVH. `gltf-mesh` exports `isPendingModelPick`, for handlers that receive a model event.
