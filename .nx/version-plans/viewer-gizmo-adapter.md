The view cube runs as graphics' `viewportGizmo` child: a gesture machine (`viewportGizmoGestureMachine`, `idle → pressed → turning`, with `pressed --after(idleStart)--> idle`) around a callback adapter (`createViewportGizmoAdapter`) that owns the `ViewportGizmo`, its listeners, its render subscription and its size follower. `ViewportGizmoCube` hands graphics the adapter from its group's ref with the new `viewportGizmoAttached` and `viewportGizmoDetached` events, and takes the section plane picker as a `planePicker` prop. A turn of the cube reaches the camera as `poseObserved` with the source `gizmo`, so the controls adapter stays the only `camera-controls` listener. The cube is built once per adapter start, inside one `gizmo.create` load span: the theme, the accent, high contrast, a web font arriving and graphics' up axis repaint it in place. `GraphicsProvider` reports the viewer environment with the new `viewerEnvironmentChanged` graphics event, and graphics forwards it and the up axis to the cube. The interaction lock is the gesture's `interactionLocked` tag, read with the new `selectGraphicsViewportGizmoLocked`; the controls adapter does not step the controls while it is held. Remove the `graphics/three/controls/viewport-gizmo-interaction-lock` subpath (`ViewportGizmoInteractionLockProvider`, `useViewportGizmoInteractionLock`, `createViewportGizmoInteractionLock` and `ViewportGizmoInteractionLock`), `bindViewportGizmoControls`, `useViewportGizmoRenderLoop`, `SectionPlanePickerContext` and `useGizmoResizeSync`, which `followGizmoCanvasSize` replaces. The view cube no longer binds OrbitControls-style controls. `GraphicsContext` gains `viewportGizmo` and `viewerEnvironment`. The section plane picker lives as long as the view cube, not only while Section is on.
