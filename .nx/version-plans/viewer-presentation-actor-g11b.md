GLB preparation moves out of React into a `presentation` actor that graphics spawns for each view (G11b). Graphics sends it each GLB request from `updateArtifact` (the bytes, revision, key and unit) and `clear` when the artifact clears or is not a GLB. The actor walks `idle → preparing → awaitingAnalysis → presented | failed`, correlated by revision and key. The mounted `GltfMesh` builds the host that parses, annotates and builds the scene, and hands it over from its asset group's ref callback as `presentationHostAttached` (and `presentationHostDetached` when it leaves); the actor spawns that host, sends it each request, and stops it when the mesh leaves or a new host replaces it. `createPresentationHostAttach` is exported from `gltf-mesh` as that ref callback. The world conventions `canonicalGltfWorld` and `tauWorld` move to `graphics/world-conventions`, which does not load Three.js, so the graphics machine no longer pulls it in; `graphics/three/gltf-world` no longer exports them (breaking). `GraphicsContext` gains `presentationRef`, `componentFocus`, `framedFocusComponentId` and `presentedManifest`.

Breaking: `GltfMesh` no longer takes `gltfFile` or `presentationRevision`; it presents the GLB that graphics was sent with `updateArtifact`, so a host that renders `CadViewer` with a GLB must also send graphics `updateArtifact`. Graphics, not the mesh, now frames a focused component of the presented unit, including a focus another view set before this view's commit, at the bounds of the geometry this view presents. Graphics observes the focus only on a model interaction it owns; a host that shares one model interaction across views sends each view `componentFocusObserved` (built with the exported `selectComponentFocus`, compared with `sameComponentFocus`) when the focus changes. A request's manifest carries the request key as its geometry hash, or none for an empty key.
