An external agent is a coding CLI you already have installed. Tau starts it, gives it the project, and shows its work in the chat — it does not resell it.

## Supported CLIs

| Agent       | Adapter                                        | CLI      | Minimum CLI |
| ----------- | ---------------------------------------------- | -------- | ----------- |
| Codex       | `@agentclientprotocol/codex-acp` 1.7.0         | `codex`  | 0.148.0     |
| Claude Code | `@agentclientprotocol/claude-agent-acp` 0.70.0 | `claude` | 2.1.232     |
| Grok Build  | Native ACP (no adapter package)                | `grok`   | 1.0.41      |

An older CLI is refused before the turn starts, naming the version found.

Only macOS is qualified: Codex and Claude Code with live turns, Grok Build not yet. Windows and Linux are unqualified for external agents until a device run is recorded.

## Install and sign in

Install each CLI on the host with its vendor's script, in table order, then sign in. macOS and Linux:

```bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
curl -fsSL https://claude.ai/install.sh | bash
curl -fsSL https://x.ai/cli/install.sh | bash
```

Windows PowerShell:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"
irm https://claude.ai/install.ps1 | iex
irm https://x.ai/cli/install.ps1 | iex
```

| Agent       | Sign in             | Update          |
| ----------- | ------------------- | --------------- |
| Codex       | `codex login`       | `codex update`  |
| Claude Code | `claude auth login` | `claude update` |
| Grok Build  | `grok login`        | `grok update`   |

`claude update` skips Homebrew and WinGet installs; use their package manager.

Tau searches `PATH`, then each vendor's install directories, including ChatGPT.app and Claude.app on macOS, so Finder, the Start menu and a terminal find the same CLI. npm and version-manager installs are found on `PATH` only.

A refused agent shows its reason and, when you can act, the install or update command. A CLI that does not answer is reported unavailable, not missing. Tau Desktop re-checks refused agents on its next listing; restart `tau serve` after installing.

Agents run on a Tau Host: Tau Desktop, or `tau serve` paired with the browser. A browser tab with no host refuses the turn instead of answering with Tau.

Each agent keeps its own configuration directory — `CODEX_HOME`, `CLAUDE_CONFIG_DIR`, or `GROK_HOME`. Tau credentials and provider API keys never reach the child process.

## Where the agent works

Each chat picks where the agent works; every turn is recorded in history, which the agent reads with the read-only `history` tool.

- **Direct** — the agent works in the project folder itself. Its edits are the files you are looking at.
- **Candidate** — the host materializes a checkout, the agent works there, and the result comes back as a branch you can review and merge.

Tau Desktop and `tau serve` offer both. Chat and run records under `.tau/chats` and `.tau/runs` refuse agent writes; the history store is hidden. [Workbench records](./workbench-records) differ: `arrange_workbench` writes at the live project root, including candidate turns. The editor applies them, and the card offers Restore.

## What reaches the vendor

The agent is the vendor's own client, so what it reads it may send. In direct mode that is your project tree. The CAD context Tau adds — the kernel, the open files, the model state — rides the session's first prompt as embedded resources, and is sent the same way.

## Billing and sign-in

The vendor bills the account you signed that CLI into. Tau charges no credits and quotes no price for an external turn: the chat footer names the agent, the model and the vendor's own usage report.

Tau never brokers or runs a login. A logged-out agent's card lists Tau's sign-in command first, with the CLI's full path when it is outside `PATH`.
