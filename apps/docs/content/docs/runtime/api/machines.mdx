# Machines API

Import browser-safe contracts from `@taucad/runtime/machine`. `MachineClient` is the machines facet that a workbench, Tau's agent tools and external agents share. Four kinds of operation cause a physical effect: `applyAction` (one declared action), the hold operations (a control held down), `stop`, and `resolveJob` (the only way a program is transferred or started). `approveAction` authorizes one; every other operation reads, binds or reconciles. An accepted receipt means the machine took the command, not that its physical result has happened.

## Discovery and binding

`listProviders` takes `MachineListProvidersInput` and returns the admitted `MachineProvider` descriptors. Show a provider the host marks `unavailable` with its reason, not as a choice; `discover` refuses it with `MACHINE_PROVIDER_UNAVAILABLE`. `discover` takes `MachineDiscoverInput` for one provider and configuration; its `MachineDiscoveryFrame` stream carries `MachineDiscoveryEvent` values. An optional `endpoint`, a `MachineEndpoint` (network address, or serial path), searches only there; another transport is refused with `MACHINE_DISCOVERY_ENDPOINT_INVALID`. A `MachineCandidate` holds a transient `MachineCandidateEndpoint` (a `MachineEndpoint` plus its network interface) and an untrusted `MachineClaimedIdentity`. `beginBinding` takes `MachineBeginBindingInput`, a non-secret ceremony, and returns `MachineBindingOutcome`; native code completes credentials and trust. `removeBinding` takes `MachineRemoveBindingInput` and returns `MachineBindingRemoval`; it is refused while a job of that machine is between preparation and start. `machineCredentialReference` creates the host-local reference to a saved credential, not a portable secret. `isSimulatedMachine` reads a manifest or a descriptor's capabilities: one that declares qualifications, all in simulation, is a simulator. Never test a provider id.

Import `prepareMachineWebSocket`, `PrepareMachineWebSocketInput` and `PreparedMachineWebSocket` from `@taucad/runtime/transport/websocket`. The helper probes an exact authenticated HTTP(S) endpoint. A `204` yields a `RuntimeTransportFacet` whose `connect()` opens a fresh channel; `403` returns `not-granted` and `404` returns `unsupported`. Redirects and URL credentials are refused.

## Directory and observation

`list`, `get` and `watch` take `MachineListInput`, `MachineGetInput` and `MachineWatchInput` and yield `MachineDirectorySnapshot`, `MachineDirectoryEntry` and streamed `MachineDirectoryFrame` values. A frame is a `snapshot`, an `event` that upserts or removes an entry, an `observed` delta for one machine's components, or `resync-required` with a fresh snapshot. `MachineDirectoryCursor` resumes a watch; it is not a mutation authority.

An entry pairs a `MachineDescriptor` with a `MachineSnapshot` and a freshness. The descriptor's `MachineCapabilities` are the `MachineInstalledCapabilities` now present plus a `revision`, an `incarnation` and the provider's `qualifications`: a changed revision invalidates every form shown before it. The snapshot is the provider's `MachineReport` plus Tau's recent operations. A report carries a `MachineState` whose `MachineStatus` is one of `machineStatuses`, the current `MachineRun` with its `MachineRunProgress` and `MachineRunCounter` values, active `MachineAlert` entries, `MachineAvailability` per declared action, and component observations.

Each `ComponentObservation` has its own receive time and validity, and either a `MachineComponentValue` or `unknown` with a reason. Values include `MachineReading` (temperatures, fans, signal), `MachineTool`, `MaterialSlotSnapshot` (addressed by `MaterialSlotAddress`, holding a `SlotMaterial`) and machine-held `MachineTable` rows such as `CalibrationProfile`. A `MachineActivity` lists `MachineActivityStep` entries; a `MachinePrompt` is the machine's current question with its `MachinePromptAnswer` choices. Standard group ids are `machineObservationGroups` (`MachineObservationGroup`); a vendor group is namespaced `<vendor>.<name>` and is read by its label. `componentValue` reads one component's value of one kind; `mergeComponentObservations` folds a delta into a list.

`captureStill` takes `MachineCaptureStillClientInput` and returns a short-lived `MachineStill` only when the machine declares still capture.

## Actions

A `MachineActionDescriptor` names its component, a standard family or a `<vendor>.<area>.<verb>` id, a version, a parameters form, its `MachineActionEffect` values (from `machineActionEffects`), a scope (`idle`, `run` or `any`), the statuses it applies in, a `MachineActionSafety` floor, a `MachineActionQualification`, the observation groups that must be fresh, and how its effect is confirmed. An action that pauses or ends a run declares its `MachineHaltOutcome`; a blocked action names a `MachineRemedy`: an action, a person's step, or `stop` with its `consequence` when only Stop ends the effect early. `standardMachineActions` lists the standard families by `StandardMachineActionId`, with parameters typed by `StandardMachineActionParameters`.

Before offering or sending, run `checkMachineAction` with a `MachineActionCheckInput` over a `MachineActionCheckEntry`; `machineActionOf` finds the installed descriptor. The pure `MachineActionCheck` is `available`, `approval-required` (an agent asks, a person approves this exact intent) or `unavailable` with a `MachineFailure` and remedy. The check is advisory: the host repeats every step with facts only it has.

`machineActionIntent` builds a complete `MachineApplyActionInput` from the entry and descriptor: machine, component, capability revision, version and the run the caller saw. `applyAction` sends it once and returns a `MachineReceipt` of kind `action`. Keep the `operationId` across reconnects and reloads; the same id never applies twice. Refusals carry a `MachineFailureCode` from `machineFailureCodes`.

## Holds and stop

A hold is a control that acts while a person holds it: the standard held jog in `standardMachineHolds`. A `MachineHoldDescriptor` declares a `lease` (how often the client renews) and a `bound` (how far the machine can keep moving after the last renewal). `beginHold` takes `MachineBeginHoldInput` with `MachineJogHoldParameters` and returns a `MachineHold`; call `renewHold` within the lease and `endHold` to finish. A hold that stops being renewed stops the machine within its bound with no message arriving. Holds are for a person at the machine only, while it is ready.

`stop` takes `MachineStopInput` and returns a `MachineReceipt` of kind `stop`. It needs no run or revision, nothing gates it, and anyone may call it. The descriptor's `stop` is a `MachineHaltOutcome` stating what halting leaves running and how to recover. A stop sent over a network or cable is not a safety-rated emergency stop.

## Authority, attendance and qualification

Every request names a `MachineRequester`. A descriptor's `MachineAuthority` floor is `agent` (admitted only for the host's low-risk list, see `isUnattendedAction`), `approved-agent` (a person, or an agent after a person approved this exact intent) or `person`. A person approves on their own session: `approveAction` takes `MachineApproveActionInput` (the agent's `operationId`, the intent shown with its run, `approve` or `deny`) and returns `MachineActionApproval`. The host keeps it with an intent digest for 10 minutes; a restart drops it. The agent's matching intent and `operationId` is admitted once; anything else, a denial included, is refused with `MACHINE_ACTION_APPROVAL_REQUIRED`. Agent sessions never approve actions or decide jobs. A provider or host setting may raise a floor, never lower it. `attended` is a person's statement that they are at the machine: recorded with the operation, refused from an agent, and not a safety function. Interlocks named by an action must report safe.

A qualification is `qualified` against a `MachineQualificationProfile` (hardware or simulation evidence for a model and firmware), or `designed` or `unsupported` with a reason. Simulation never qualifies hardware. `setTesting` takes `MachineSetTestingInput` and returns the updated entry: in Testing mode a person may try `designed` controls on that machine to qualify them. Testing is a person's mode: an agent's request for a `designed` action is refused with Testing on.

## Jobs

`checkJob` takes `MachineCheckJobInput` and returns a `MachineJobCheck`: the parsed `MachineProgramSummary`, each `MachineCheck`, and the completed start-form values, or a refusal. It sends nothing and records nothing. `requestJob` takes `MachineRequestJobInput` and returns a `MachineJob`; the same `jobId` returns the existing job. `listJobs` and `watchJobs` take `MachineListJobsInput`; when `watchJobs` completes, list and watch again.

A job moves through `MachineJobState` values from `preparing` and `awaiting-approval` to `started`, or ends `denied`, `withdrawn`, `rejected`, `unknown` or `failed`. `MachinePreparedJob` binds artifact, machine, configuration and setup digests with an expiry. `resolveJob` takes `MachineResolveJobInput`: approval carries the attestations the person made, their attendance, and the transfer and start operation ids the host will use. Only a person's session decides a job; the agent then reads it. `withdrawJob` takes `MachineWithdrawJobInput`. The descriptor's `MachineJobFacts` say whether delivery is `stored` or `streamed` and whether a person starts the job at the machine.

## Operations

Each effect is a `MachineOperation` of one `MachineOperationKind`, with one state from `planned` through `sending` to `accepted`, `rejected` or `confirming`; `attention` asks a person to look when no proof arrives. A `MachineOperationReceipt` is `accepted`, `rejected` or `unknown`. Nothing is resent: `reconcileOperation` takes `MachineReconcileOperationInput` and reads what happened.

```ts
import { checkMachineAction, machineActionIntent } from '@taucad/runtime/machine';
import type { MachineClient, MachineDirectoryEntry } from '@taucad/runtime/machine';

export const turnOnLight = async (client: MachineClient, entry: MachineDirectoryEntry): Promise<string> => {
  const check = checkMachineAction({
    entry,
    componentId: 'chamber-light',
    action: 'switch.set',
    caller: 'person',
    attended: false,
    now: Date.now(),
  });
  if (check.status !== 'available' || !('scope' in check.descriptor)) {
    return check.status === 'unavailable' ? check.message : 'Needs approval';
  }
  const receipt = await client.applyAction(
    machineActionIntent(entry, check.descriptor, {
      operationId: crypto.randomUUID(),
      parameters: { on: true },
      requestedBy: { kind: 'user', id: 'local', label: 'You' },
    }),
  );
  return receipt.status; // 'accepted', 'rejected' or 'unknown'
};
```

## Saved machine settings

Import persistence helpers from `@taucad/runtime/machine/settings`. A `MachineTypeId` identifies a namespaced machine type; `machineTypeIdSchema` rejects unsafe path spellings. `machineSettingsPath({ typeId })` returns `.tau/machines/settings/<typeId>.json` within the project. These files contain preferences, not credentials or permission to operate hardware.

`MachineSettingsRecord` stores version `1`, the machine type, an active `MachineProfileId`, and named profiles. Each `MachineSettingsProfile` maps configuration IDs to `SavedMachineConfiguration` blocks with an exact source version and sparse JSON values. Inactive and unknown blocks remain preserved.

| Helper                                                                         | Result and failure contract                                                                                                                                                                                    |
| ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `readMachineSettings({ bytes, typeId })`                                       | Returns `ReadMachineSettingsResult`: an immutable current record or `MachineSettingsFailure`. Refusals distinguish invalid data, a newer record version, and a different machine type. Preserve refused bytes. |
| `serializeMachineSettings({ record })`                                         | Validates and writes deterministic JSON with a trailing newline. Throws for invalid records or output above `machineSettingsMaximumBytes` (262,144 UTF-8 bytes).                                               |
| `readMachineConfiguration({ settings, profileId, definition, signal })`        | Returns `ReadMachineConfigurationResult` with absent, current, or refused status. Current `SavedSettingsValues` are deeply immutable.                                                                          |
| `setMachineConfiguration({ settings, profileId, definition, values, signal })` | Produces a replacement record without I/O. Passing `undefined` removes that configuration block. Persist the returned record through a checked write.                                                          |

A `SettingsSchema` admits sparse JSON objects. A `SettingsDefinition` preserves the schema's input and output values: validation cannot inject defaults or transform persisted values. `MachineProfileFailure` reports a missing selected profile. `MachineConfigurationFailure` reports an unsupported configuration version or invalid values; neither refusal falls back to defaults.

`MachineSettingsProvenance`, validated by `machineSettingsProvenanceSchema`, captures project scope, type, profile, and exact configuration versions for a prepared job. Subsequent preference edits do not change captured provenance.

### Host ownership

Import `MachineSettingsOwner` and its boundary types from `@taucad/runtime/host`. Construct it with an exact rooted filesystem supporting bounded streaming reads and checked writes, plus trusted definitions. Its `read` and `subscribe` methods return `MachineSettingsSnapshot`, distinguishing current, absent, refused, and unavailable records.

An edit supplies a `MachineSettingsEdit`: operation ID, type ID, captured base record, and proposed next record. `MachineSettingsSave` reports saved, conflict, refused, or uncertain. Keep the operation ID and call `settlement` after an uncertain result; never treat uncertainty as success. Call `dispose` when done.
