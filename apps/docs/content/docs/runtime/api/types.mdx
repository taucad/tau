Document results always carry `issues`. Successful evaluations offer ordered view and export IDs, including an empty view list. A rendering correlates `requestId` and `evaluationId`; its `artifact` carries MIME type, content, and optional units. `hash` identifies its projected artifact. Successful exports carry a nonempty file tuple. Optional `sourceRevision` records evaluated source provenance.

`DocumentStatus` and `ViewStatus` describe separate owners. Their events and supersession outcomes are documented in [Client API](./client).

## Published parts and assemblies

An authored assembly names source recipes and occurrences under the client's rooted project filesystem. `AuthoredAssemblySource` selects either a project path or an in-memory file map; `AuthoredPartRecipe` selects source or an already issued part reference. Each `AuthoredPartOccurrence` is a group or a leaf. Publication resolves each leaf to an explicit variant in `PublishedPartOccurrence`.

<auto-type-table path='./props/types.ts' name='AuthoredAssembly' />

<auto-type-table path='./props/types.ts' name='AuthoredAssemblySource' />

<auto-type-table path='./props/types.ts' name='AuthoredPartOccurrence' />

<auto-type-table path='./props/types.ts' name='PublishedPartOccurrence' />

`PublishedPartRecord` is the durable, versioned set of effective recipes. Each `PublishedPartVariant` pins a display GLB through `PublishedPartAsset`; `PublishedPartExact` adds optional native evidence and its producer-qualified codec. The host issues a digest-pinned `PublishedPartReference` to the record. `publishedPartRecordSchema` validates the record at wire and durable boundaries, including its asset and exact metadata.

`PublishedAssembly` carries checked records and occurrences. `AssemblyDisplayProjector` is the trusted host-local admission/projection callback: admission validates the immutable closure, while projection returns flattened display bytes. `AdmittedAssembly` adds a client-local asset reader after host admission; callers do not construct its token. A `PublishedAssemblyRootSnapshot` observes the current shared root and generation, but cannot reconstruct a lost caller receipt. `PublishAssemblyOutcome` distinguishes published, superseded, cancelled, invalid, and commit-unknown outcomes; after commit-unknown, use its `readCurrent` callback before deciding what to do next.

`PublishedAssemblyDocument` is the source-free session returned for an admitted root. Close it independently of an authored document. `PublishedExportInput` selects either a part reference and variant or an assembly root with optional `PublishedAssemblyComponentPlacement` values. A placement moves restored native geometry for one admitted canonical component without changing the pinned root. `ExportOutcome` carries admitted files or issues. `selectPublishedExportRoute` examines admitted metadata and declared capabilities to choose an eligible route; execution still validates immutable assets and the exact codec.
