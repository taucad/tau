Use the autonomous render loop when a viewer must redraw on parameter changes, file edits, or option updates. Push intent with `client.render`, `client.updateParameters`, and `client.setOptions`; consume settled geometry on the `geometry` event. For a single render-and-export cycle, `client.export(format, input)` needs no event subscription — see the [Quick Start](../getting-started/quick-start).

## 1. Create the client

```typescript
import { createRuntimeClient } from '@taucad/runtime';
import { defineRuntime } from '@taucad/runtime/worker';
import { replicad } from '@taucad/replicad';
import { fromMemoryFs } from '@taucad/runtime/filesystem';
import { inProcessTransport } from '@taucad/runtime/transport/in-process';

const runtime = defineRuntime({ plugins: [replicad()] });
export const client = createRuntimeClient({
  transport: inProcessTransport({ runtime, fileSystem: fromMemoryFs() }),
});
```

Inline `source.files` input is staged into this transport-owned filesystem; `source.entry` selects a key from that map. A filesystem-backed `source.path` is a canonical root-relative [runtime path](../concepts/path-namespaces). Raw transports need an explicit `fileSystem`; helpers such as `createNodeClient()` and `createWebWorkerClientOptions(...)` provide one. For hosted filesystem mappings, see [Embedding in a Host](./embedding-in-a-host).

## 2. Subscribe to the geometry event

`client.on('geometry', handler)` invokes the handler once per render result with a [`HashedGeometryResult`](../api/types) — a `KernelResult` whose `success: true` branch carries geometry and whose `success: false` branch carries structured `KernelIssue`s. It returns an unsubscribe function:

```typescript
import type { RuntimeClient } from '@taucad/runtime';

export const attachViewer = (client: RuntimeClient): (() => void) =>
  client.on('geometry', (result) => {
    if (result.success) {
      console.log(`Rendered ${result.data.format} geometry`);
      return; // hand result.data to your viewer
    }
    for (const issue of result.issues) {
      console.error(`[${issue.severity}] ${issue.message}`);
    }
  });
```

Retain the unsubscribe function and call it when the component unmounts — the handler closes over your viewer, so leaking the subscription leaks the viewer.

## 3. Render a source

`client.render(input)` hands the worker a source and parameters and starts the loop. Its Promise settles with a `RenderOutcome` discriminated union:

- `{ superseded: false, geometry }` — this call's render produced the geometry now visible.
- `{ superseded: true }` — a newer public command or autonomous watched-filesystem preview took ownership first. The selected geometry arrives over the event channel.

Supersession is not an error. It is the normal outcome whenever a user drags a slider faster than the kernel can re-mesh.

```typescript
import type { RuntimeClient } from '@taucad/runtime';

export const renderModel = async (client: RuntimeClient, code: string): Promise<void> => {
  const settlement = await client.render({
    source: { files: { 'main.ts': code } },
    parameters: { width: 50, depth: 15 },
  });
  if (settlement.superseded) return; // the latest geometry is on its way over the event channel
  console.log(`Rendered ${settlement.geometry.success ? 'ok' : 'failed'}`);
};
```

## 4. Push parameter updates

Once a render has opened a file, `client.updateParameters(...)` debounces in the worker, re-renders, and emits on the `geometry` event. It settles with the same `RenderOutcome` shape, so a slider drag firing three updates in 16ms yields two superseded settlements and one settled geometry:

```typescript
import type { RuntimeClient } from '@taucad/runtime';

export const onSliderChange = async (client: RuntimeClient, width: number): Promise<void> => {
  const settlement = await client.updateParameters({ width });
  if (settlement.superseded) return; // a newer drag value won
  if (settlement.geometry.success) console.log(`Settled at width=${width}`);
};
```

Unlike `render` and `export`, which connect lazily, `updateParameters` and `setOptions` require a connected client — they reject with `RuntimeNotConnectedError` before `connect()` or an opening command settles. See [Handle Errors](./error-handling).

## 5. Replace render options

Per-render kernel options — tessellation tolerances, for example, when the active kernel exposes them — are replaced with `client.setOptions(...)`. The call awaits the next render's settlement:

```typescript
import type { RuntimeClient } from '@taucad/runtime';

export const applyTolerance = async (client: RuntimeClient): Promise<void> => {
  const settlement = await client.setOptions({
    renderOptions: { tessellation: { linearTolerance: 0.05 } },
  });
  if (!settlement.superseded && settlement.geometry.success) {
    console.log('New options applied');
  }
};
```

Use `setOptions` for UI toggles that change how the kernel renders — not for one-off export options, which belong on the `client.export(format, input)` call.

`client.setRenderTimeout(ms)` is a separate connected-client setter: it returns `void` and applies only to renders that begin after the call; `0` disables enforcement. See [Configure Render Timeouts](./render-timeouts).

## 6. Clean up

Unsubscribe the `geometry` listener, then call `client.terminate()`. Termination is idempotent and synchronous: `client.lifecycleState` becomes `'terminated'` and every subsequent command rejects with `RuntimeTerminatedError`.
