tscircuit is Tau's EDA kernel. `@taucad/tscircuit` claims `.tsx` and `.jsx` files, bundles them with the runtime bundler, evaluates the board once with `@tscircuit/core`, and keeps the settled circuit JSON as the native handle. It runs in browser workers and Node hosts and never reaches the network while rendering or exporting.

## Authoring contract

Each entry file default-exports one board component. `React` is provided as a global by the worker, so the import is optional. Every component needs a unique `name`; footprints are footprinter strings such as `0402`, `0603`, `soic8`, or `dip8`; positions are millimetres.

```tsx
export default () => (
  <board width='20mm' height='20mm'>
    <resistor name='R1' resistance='1k' footprint='0402' pcbX={-4} pcbY={0} />
    <led name='LED1' color='red' footprint='0603' pcbX={4} pcbY={0} />
    <trace from='.R1 > .pin2' to='.LED1 > .anode' />
  </board>
);
```

Traces use tscircuit selectors (`.R1 > .pin1`, `net.GND`). Optional `defaultParameters` exports become editable parameters that Tau passes to the component as props.

## Views and exports

One evaluation retains the settled circuit JSON. It offers these separately declared views from that handle:

| View ID     | Artifact                        |
| ----------- | ------------------------------- |
| `board`     | GLB board with component bodies |
| `schematic` | Schematic SVG                   |
| `pcb`       | PCB layout SVG                  |

The kernel declares export IDs `board` (GLB), `bom` (CSV), `netlist` (text), and `circuit` (JSON). Each has its own title, MIME type, extension, and optional options schema. A schematic-only result may offer only the schematic view; the ordered offers are returned by `evaluate`.

The current client renders the first offered view and still addresses exports by extension. It cannot select `schematic` or `pcb` through a global `renderOptions.output` setting; explicit view selection arrives with the W3 document-view client migration. Kernel authors can already call the v2 `evaluate`/`render` hooks directly in isolated tests.

## Offline behaviour

The circuit uses the local autorouter and no parts engine. `fetch` is disabled during evaluation and GLB conversion, so `http(s)://` footprint and `cadModel` URLs are never requested; each attempt becomes a `warning` naming the URL. Library references (`kicad:`, `jlcpcb:`) produce a `warning` and an unplaced part. The render completes with local bodies and bounding boxes.

## Install note for zod

Several tscircuit packages (`@tscircuit/props`, `@tscircuit/circuit-json-util`, `@tscircuit/soup-util`, `circuit-json`) target the zod 3 API but declare zod as a loose peer or not at all. In a zod 4 workspace they resolve zod 4 and fail at load. Until upstream manifests are zod-4 clean, add this pnpm hook to the consumer's `.pnpmfile.cjs` so zod 3 nests under them:

```javascript
const zod3Consumers = new Set([
  '@tscircuit/props',
  '@tscircuit/circuit-json-util',
  '@tscircuit/soup-util',
  'circuit-json',
]);

function readPackage(pkg) {
  if (zod3Consumers.has(pkg.name)) {
    delete pkg.peerDependencies?.zod;
    pkg.dependencies = { ...pkg.dependencies, zod: '^3.25.76' };
  }
  return pkg;
}

module.exports = { hooks: { readPackage } };
```
