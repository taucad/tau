# @taucad/project-library

The project library of the Tau UI app: its four machines (discovery, recovery, access and the project manager), entry and journal types, storage calls and filesystem observations, the `ProjectLibrary` service and its commands, and the project manager's provider and listing hook, behind injected seams. A project carries its chats, so the library writes into chat storage (`@taucad/chat-ui`) as well as the file system (`@taucad/files-ui`), and lives above both. Private and source-consumed (`scope:ui type:app-lib`, layer L2 of the UI app library layering): `apps/ui` imports it; it imports the foundation (`ui-core`, `ui-kit`) and the `chat-ui` and `files-ui` features, never `apps/ui`, another composition library or the agent-host adapters.

Cut from `files-ui` in layering W5, which took `files-ui` off `chat-ui` and `@taucad/chat`. Home and the project route both read it, so it is not route-private and does not belong in `project-workspace`.

## Entrypoints

One subpath per module, pinned by `src/exports.test.ts`. Audience: `apps/ui` (the library's app binding, the project manager hook and the project listing).

| Subpath             | Contents                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `./hooks/<name>`    | `use-project-manager` (`useProjectManager` and its context), `project-manager-provider` (`ProjectManagerProvider` over one `ProjectLibrary`), `use-projects` (`useProjects`: the listing filtered to a scope, and the project gestures)                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `./machines/<name>` | `library-discovery.machine`, `library-recovery.machine`, `library-access.machine` (the project library's discovery passes, journal recovery and access questions; `LibraryCatalog.tla`), `project-manager.machine` (the object-store worker's lifecycle)                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `./runtime/<name>`  | `project-library` (`ProjectLibrary`: the library service over its machines, worker and chat store), `project-library-commands` (`ProjectCommands`: create, duplicate, trash, restore, delete, adopt, repair and rename), `project-library.fixture` (a replaceable root file facade for library tests), `project-library-storage` (discovery, commit, route-access and listing calls the library machines run), `project-library-observations` (the manifest and chat-metadata watches, and the metadata read owner), `project-library-workspace` (`WorkspaceCommands`: connect, retry, refresh and repair workspaces), `project-library-chat-logs` (a closed project's chat-log lease, loaded only on delete) |
| `./types/<name>`    | `project-library.types` (library state, entries and list items), `pending-project-operation.types` (the pending-operation journal and its recovery reasons), `project-library-io.types` (the structural facade, object-store and chat-store contracts the app's values satisfy, and `AppUiPreferences`), `chat-storage.types` (`ChatStorage`, the chat store's contract the app's chat file store implements)                                                                                                                                                                                                                                                                                                 |

## Seams

The three library machines are the formal core of `ProjectLibrary`: `apps/ui/specs/library-catalog` checks them against `LibraryCatalog.tla` and hashes them in this library, so a change to one goes through that spec first (`FORMAL_UPDATE=1`). `runtime/project-library-storage` and `runtime/project-library-observations` are the calls and watches the machines run as ports. They take the facade, the object-store worker and the chat store as arguments typed by `types/project-library-io.types` (`ProjectLibraryFileManager`, `ProjectLibraryObjectStore`, `ProjectLibraryChatRecords`): only the members they read, so the app passes its `ProjectLibraryFacade`, `Remote<ObjectStoreWorker>` and chat store unchanged. The storage root key reads the database prefix from `@taucad/ui-core/constants/meta.constants`, the value the app hands its file-manager worker. `machines/workspace-connection.machine` reports its first fault through the `reportFault` member of its injected services, and `runtime/project-library-workspace` reads the facade's `workspace` and the worker's journal (`WorkspaceJournal`) structurally, so `ProjectLibrary` passes its runtime fault reporter, facade and `Remote<ObjectStoreWorker>` in. `machines/project-manager.machine` holds the object-store worker: its input (`ProjectManagerServices`) carries `startObjectStore`, which returns the worker and its store as `ProjectLibraryObjectStore`, plus `reportFault` and `reportWorkerFailed`. `ProjectLibrary` passes its worker factory, `reportAppRuntimeFault` and `reportProjectLibraryWorkerFailed`, and reads the store back as its worker.

`runtime/project-library` (`ProjectLibrary`) and `runtime/project-library-commands` (`ProjectCommands`) run them. Both are generic over the worker (`ProjectLibraryWorker`), the root facade (`ProjectLibraryRootFacade`) and the chat projection, and take what only the app supplies as `ProjectLibraryServices`: `startObjectStore`, `reportFault`, `reportWorkerFailed`, `buildSkew` (the write stop a newer build sets), `createChatStore`, `clearLegacyListing`, and the commands' `ProjectCommandsServices`: `projectTemplates` (the project constants and the kernel helpers, which read the kernel plugins' lock files), `buildUserMessage`, `cloudIntent` (Tau Cloud's backup intent) and `isCaughtUp` (a chat projection's catch-up). `apps/ui/app/runtime/project-library.ts` is the app's binding: a `ProjectLibrary` subclass that fixes the three types and passes services that read their app modules when called, so a suite that mocks one of those modules still reaches the library through it. The create-project lock is `withNamedLock` from `@taucad/ui-core/lib/named-lock`, shared with the app's Tau Cloud gestures.

`hooks/project-manager-provider` composes a `ProjectLibrary` into the value `useProjectManager` (`hooks/use-project-manager`) reads. Its worker is a `ProjectManagerWorker` (the library's worker plus the GeoSpec consent and the chrome preferences), and it takes what only the app supplies as `ProjectManagerServices`: `generateProjectName`, `seedChatPermission`, `removeChatPermission` and `prepareFirstProjectTour`. The context lives in `use-project-manager`, apart from its provider, so an edit to the provider keeps it. `hooks/use-projects` takes the project manager, the chat session store and the view exceptions as inputs (`ProjectsInputs`). The app keeps bindings at `hooks/use-project-manager.tsx` and `hooks/use-projects.ts`: the first resolves the runtime's library and passes its services, and re-exports `useProjectManager`; the second passes the app's `useProjectManager()` result, so suites that mock either app path still reach every reader.

The library reads these `files-ui` modules: `workspace-connection.machine`, `handle-store`, `desktop-bridge`, `orphaned-project-route`, `browser.constants`, `project-url.utils`, `project-name.utils` and `workspace-telemetry.utils`.

## Still in the app

The project library's app binding stays at `runtime/project-library.ts`, with what it binds: the object-store worker (`hooks/object-store-worker`, started by `new URL(…, import.meta.url)`), the reporters (`app-runtime-faults`, `file-service-reports`, both through `#lib/error-reporting`), `filesystem/build-skew` (`#lib/build-identity`, which reads `window.ENV` and build globals), `db/chat-file-storage` (the app's chat store), `constants/project.constants` (named by path by `scripts/src/check-standalone-project.ts` and the native Darwin lane paths in `ci.yml`), `utils/kernel.utils` (`?raw` lock files), `utils/chat.utils` (the app version in `metaConfig.userAgent`, and types from `#hooks/use-models`), `lib/tau-cloud-intent` (the revision session user) and `machines/chat-projection.logic` (the chat SDK loader). So do its test rows that need the app runtime or device storage, and `runtime/project-library.fixture.ts`, which types this library's fixture by the app's facade. The app's facade type `ProjectLibraryFacade` stays in `runtime/file-manager-facade.ts` (it is `Pick<ReturnType<typeof useFileManager>, …>`). The `use-project-manager` suites stay in the app: they compose the app's `ProjectLibrary` binding and runtime and mock its modules. `types/storage.types.ts` keeps the app's object-store contract; only `ChatStorage` and `AppUiPreferences` moved.
