# Bundler API

Use the bundler API when configuring how JS/TS kernel inputs are bundled and executed. Bundlers resolve imports, transpile code, and produce executable bundles for the kernel runtime.

## esbuild

`esbuild()` installs the default esbuild-wasm bundler toolkit. Use `esbuildBundler(options)` only when configuring the role factory directly. Both handle `ts`, `js`, `tsx`, `jsx` by default.

## defineBundler

`defineBundler` creates a bundler definition from a configuration object. Required methods: `initialize`, `detectImports`, `bundle`, `execute`, `registerModule`. Optional: `resolveDependencies`, `cleanup`.

Bundler operation methods use `(input, runtime, context)`. The runtime contains a fresh operation-scoped `AbortSignal`; the persistent context is the value returned by `initialize`. Methods receive `entryPath` as a normalized [runtime path](../concepts/path-namespaces) beginning with `/`. Returned dependency paths use the same namespace. The leading slash refers to the supplied runtime filesystem, not the host operating system.

## Usage

```typescript
import { createRuntimeClient } from '@taucad/runtime';
import { fromMemoryFs } from '@taucad/runtime/filesystem';
import { inProcessTransport } from '@taucad/runtime/transport/in-process';
import { defineRuntime } from '@taucad/runtime/worker';
import { replicad } from '@taucad/replicad';
import { esbuild } from '@taucad/esbuild';

const runtime = defineRuntime({
  plugins: [replicad(), esbuild()],
});

const client = createRuntimeClient({
  transport: inProcessTransport({ runtime, fileSystem: fromMemoryFs() }),
});
```
