# Client API

Use the client API when you need to create a kernel runtime, configure filesystem access, or manage worker connections. The factory and constructors are the primary entry points for integrating `@taucad/runtime` into an application.

## Worker-Owned Runtime

Executable capabilities are declared in the worker or host process with `defineRuntime`. Browser and framework clients connect with a transport and may import only `typeof runtime` for compile-time narrowing:

```typescript
// runtime.worker.ts
import { defineRuntime, createRuntimeWorker } from '@taucad/runtime/worker';
import { webWorkerHost } from '@taucad/runtime/transport/web';
import { replicad } from '@taucad/runtime/kernels';
import { esbuild } from '@taucad/runtime/bundler';

export const runtime = defineRuntime({
  kernels: [replicad()],
  bundlers: [esbuild()],
});

await webWorkerHost({ worker: createRuntimeWorker({ runtime }) }).open();
```

```typescript
// app.ts
import type { runtime } from './runtime.worker';
import { createRuntimeClient } from '@taucad/runtime/client';
import { fromMemoryFs } from '@taucad/runtime/filesystem';
import { webWorkerTransport } from '@taucad/runtime/transport/web';

const client = createRuntimeClient<typeof runtime>({
  transport: webWorkerTransport({
    createWorker: () => new Worker(new URL('./runtime.worker.ts', import.meta.url), { type: 'module' }),
    fileSystem: fromMemoryFs(),
  }),
});
```

Node tests and CLIs can use the root entry's in-process convenience by passing the runtime definition directly:

```typescript
import { createRuntimeClient } from '@taucad/runtime';
import { defineRuntime } from '@taucad/runtime/worker';
import { replicad } from '@taucad/runtime/kernels';
import { esbuild } from '@taucad/runtime/bundler';
import { inProcessTransport } from '@taucad/runtime/transport/in-process';

const runtime = defineRuntime({ kernels: [replicad()], bundlers: [esbuild()] });
const client = createRuntimeClient({
  transport: inProcessTransport({ runtime }),
});
```

## Boot Config

Runtime definitions may declare a Zod `configSchema` when worker-owned plugin construction needs deployment-specific values. The worker still owns executable composition; the client supplies only a structured-cloneable config payload before initialization:

```typescript
// runtime.worker.ts
import { z } from 'zod';
import { defineRuntime, createRuntimeWorker } from '@taucad/runtime/worker';
import { webWorkerHost } from '@taucad/runtime/transport/web';
import { zoo } from '@taucad/runtime/kernels';
import { esbuild } from '@taucad/runtime/bundler';

export const runtime = defineRuntime({
  configSchema: z.object({
    tauWebSocketUrl: z.string().url(),
  }),
  createRuntime(config) {
    return {
      kernels: [zoo({ baseUrl: `${config.tauWebSocketUrl}/v1/kernels/zoo` })],
      bundlers: [esbuild()],
    };
  },
});

await webWorkerHost({ worker: createRuntimeWorker({ runtime }) }).open();
```

```typescript
// app.ts
import type { runtime } from './runtime.worker';
import { createRuntimeClient } from '@taucad/runtime/client';
import { webWorkerTransport } from '@taucad/runtime/transport/web';

const client = createRuntimeClient<typeof runtime>({
  config: async () => loadRuntimeConfig(),
  transport: webWorkerTransport({
    createWorker: () => new Worker(new URL('./runtime.worker.ts', import.meta.url), { type: 'module' }),
  }),
});
```

The runtime factory receives `z.output<typeof configSchema>`, while the client accepts `z.input<typeof configSchema>`. Required schemas make `config` required on the client; schemas that default or accept `undefined` make it optional. Static runtimes do not accept `config`.

Invalid config fails during `connect()` with `RuntimeConnectionError.causeKind === 'runtime-config'` and a `RuntimeConfigError` code of `'RUNTIME_CONFIG_INVALID'`. Filesystem remains a transport-owned workspace resource and is not part of boot config.

## Methods

| Method             | Signature                                                                      | Description                                                                                                                                     |
| ------------------ | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `lifecycleState`   | `'unconnected' \| 'connecting' \| 'connected' \| 'terminated'`                 | Current lifecycle state. Read-only.                                                                                                             |
| `activeKernelId`   | `KernelId \| undefined`                                                        | Kernel that currently owns the worker. Updated via the `activeKernelChanged` event.                                                             |
| `capabilities`     | `CapabilitiesManifest \| undefined`                                            | Resolved capabilities manifest. Available after `connect()` completes.                                                                          |
| `connect`          | `() => Promise<void>`                                                          | Run the transport handshake and resolve the capabilities manifest. Idempotent.                                                                  |
| `render`           | `(input: RuntimeRenderInput) => Promise<RenderOutcome>`                        | Hand the worker a `(source, parameters)` pair and let it own the autonomous render loop.                                                        |
| `updateParameters` | `(parameters) => Promise<RenderOutcome>`                                       | Update parameters for the active file. Supersedes any in-flight render.                                                                         |
| `setOptions`       | `({ renderOptions?, renderTimeout? }) => Promise<RenderOutcome>`               | Replace render options and runtime-owned render timeout for the active source. Full replace, not patch — keys absent from the call are dropped. |
| `export`           | `(format, { source?, parameters?, exportOptions? }?) => Promise<ExportResult>` | Export to STEP/STL/GLB. With `source`, self-renders; without, reuses the latest render.                                                         |
| `on`               | `(event, handler) => () => void`                                               | Subscribe to a worker event. Returns an unsubscribe function.                                                                                   |
| `terminate`        | `() => void`                                                                   | Tear down the worker, transport, and event subscriptions.                                                                                       |

## Presets

`presets.all()` returns a runtime definition containing all built-in kernels, middleware, bundlers, and transcoders. Import it from the explicit presets subpath:

```typescript
import { createRuntimeClient } from '@taucad/runtime';
import { presets } from '@taucad/runtime/presets';
import { inProcessTransport } from '@taucad/runtime/transport/in-process';

const runtime = presets.all();
const client = createRuntimeClient({
  transport: inProcessTransport({ runtime }),
});
```

Use an explicit transport when you also need to bind a filesystem:

```typescript
import { createRuntimeClient } from '@taucad/runtime';
import { presets } from '@taucad/runtime/presets';
import { fromNodeFs } from '@taucad/runtime/filesystem/node';
import { inProcessTransport } from '@taucad/runtime/transport/in-process';

const runtime = presets.all();
const client = createRuntimeClient({
  transport: inProcessTransport({ runtime, fileSystem: fromNodeFs('/path/to/project') }),
});
```

## Filesystem

<auto-type-table path='./props/client.ts' name='RuntimeFileSystem' />

`fromMemoryFs`, `fromNodeFs`, `fromFsLike`, `fromBrowserFs`, and `fromFileSystemBridge` all return an opaque `RuntimeFileSystem` value. Pass it into the wired transport callable (`webWorkerTransport({ fileSystem })`, `inProcessTransport({ runtime, fileSystem })`, …); the transport constructs the kernel-side bridge primitives internally. Consumers cannot inspect or branch on the handle's kind.

### Transport plugins vs materialized handles

Bundled transports are **`TransportPlugin`** callables (`webWorkerTransport`, `nodeWorkerTransport`, `inProcessTransport`). `createRuntimeClient` receives the **wired plugin** (the result of `webWorkerTransport({ ... })` — `{ id, describe, materialize }`) and calls **`materialize()` once during client construction** to obtain the fat `RuntimeTransportClient` handle (`open()`, `initialize()`, …). Worker/kernel entries that own the opposing wire import standalone factories such as **`webWorkerHost`** / **`nodeWorkerHost`** directly — never through a `.host` accessor on the plugin callable.

## Error Types

Lifecycle errors:

- **`RuntimeNotConnectedError`** -- a command was issued before `connect()` resolved.
- **`RuntimeConnectionError`** -- the transport handshake failed. Carries a typed `causeKind`: `'transport-open' | 'runtime-config' | 'capabilities-resolution' | 'kernel-binding'`.
- **`RuntimeTerminatedError`** -- a command was issued after `terminate()`, or an in-flight Promise was rejected because `terminate()` happened mid-flight. Carries a typed `causeKind`: `'explicit' | 'connection-failed' | 'transport-closed'`.

Render errors:

- **`RenderTimeoutError`** -- the render exceeded its configured timeout (`renderTimeout`, milliseconds).
- **`RenderAbortedError`** -- the render was aborted (typically because a newer command superseded it before settlement).
- **`NoRenderOutcomeError`** -- `client.export(format)` (single-arg) was called without a prior render result.

Geometry pool errors (uncommon — surface when the SAB-backed geometry pool returns an unexpected key):

- **`SharedPoolEntryNotFoundError`** -- the worker emitted a `pooled` geometry key the runtime client could not resolve.

Use the realm-safe `isRuntimeNotConnectedError`, `isRuntimeConnectionError`,
`isRuntimeTerminatedError`, `isRenderTimeoutError`,
`isRenderAbortedError`, `isNoRenderOutcomeError`, and `isSharedPoolEntryNotFoundError`
guards for cross-realm detection.

### Error Code Reference

Every runtime error class exposes a stable `code` getter so callers can branch on the error kind without depending on `Error.message` or `instanceof` (the message is human prose; the code is the contract).

| Error class                    | `code`                              | Notes                                                  |
| ------------------------------ | ----------------------------------- | ------------------------------------------------------ |
| `RuntimeNotConnectedError`     | `'RUNTIME_NOT_CONNECTED'`           | —                                                      |
| `RuntimeConnectionError`       | `'RUNTIME_CONNECTION_FAILED'`       | Pair with the `causeKind` field                        |
| `RuntimeConfigError`           | `'RUNTIME_CONFIG_INVALID'`          | Wrapped by `RuntimeConnectionError` during `connect()` |
| `RuntimeTerminatedError`       | `'RUNTIME_TERMINATED'`              | Pair with the `causeKind` field                        |
| `RenderTimeoutError`           | `'RUNTIME_RENDER_TIMEOUT'`          | —                                                      |
| `RenderAbortedError`           | `'RUNTIME_RENDER_ABORTED'`          | —                                                      |
| `NoRenderOutcomeError`         | `'RUNTIME_NO_RENDER_OUTCOME'`       | —                                                      |
| `SharedPoolEntryNotFoundError` | `'RUNTIME_SHARED_POOL_KEY_MISSING'` | —                                                      |

`KernelIssue` payloads (delivered via the `error` event and on `Geometry` results) carry a parallel `code: KernelIssueCode` field — use it instead of `RegExp`-matching `issue.message`.

> Supersession is **not** an error. `render`/`updateParameters`/`setOptions`
> resolve a `RenderOutcome` discriminated union — the `superseded: true`
> branch is the normal outcome when a newer call takes ownership of the
> worker. See [Handle Errors](../guides/error-handling) for the full pattern.

## Event Subscription

Subscribe to client events with `client.on(event, handler)`. Returns an unsubscribe function.

| Event                 | Handler Signature                                                | When                              |
| --------------------- | ---------------------------------------------------------------- | --------------------------------- |
| `geometry`            | `(result: HashedGeometryResult) => void`                         | Render completes (autonomous)     |
| `state`               | `(state: WorkerState, detail?: string) => void`                  | Worker state changes              |
| `log`                 | `(entry: { level, message, origin?, data? }) => void`            | Kernel/middleware log messages    |
| `progress`            | `(phase: RenderPhase, detail?: Record<string, unknown>) => void` | Render phase transitions          |
| `telemetry`           | `(entries: TelemetryEntry[]) => void`                            | Performance entries               |
| `parametersResolved`  | `(result: GetParametersResult) => void`                          | Parameters extracted              |
| `capabilities`        | `(manifest: CapabilitiesManifest) => void`                       | Capabilities resolved             |
| `activeKernelChanged` | `(kernelId: KernelId) => void`                                   | A new kernel took over the worker |
| `error`               | `(issues: KernelIssue[]) => void`                                | Worker emitted a top-level error  |

## When Do I Need `connect()`?

`client.connect()` runs the transport handshake. It takes **no arguments** in v6 — every wire concern (filesystem, file pool SAB, abort signalling) is closed over by the transport supplied at construction. Call it explicitly when your host creates the client before the first command; `render` and `export` open the transport as needed, and inline source staging requires that transport to own a filesystem.

| Scenario                                             | Transport construction                                                                                                                                               | See                                                  |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| Inline `source.files` -- one-shot or live re-renders | `const runtime = presets.all(); createRuntimeClient({ transport: inProcessTransport({ runtime, fileSystem: fromMemoryFs() }) })`                                     | [Quick Start](../getting-started/quick-start)        |
| Filesystem on disk (Node.js)                         | `inProcessTransport({ runtime, fileSystem: fromNodeFs(path) })`                                                                                                      | [Set Up the Filesystem](../guides/filesystem-setup)  |
| Browser editor with FS worker                        | `const bridge = openFileSystemBridge(fsWorker); webWorkerTransport({ url, fileSystem: fromFileSystemBridge(bridge) })`                                               | [Embedding in a Host](../guides/embedding-in-a-host) |
| Zero-copy file content (filePool SAB)                | `webWorkerTransport({ fileSystem, filePoolBuffer })` or `nodeWorkerTransport({ ... })` — host-supplied buffer; `inProcessTransport` uses `files` pool sizing instead | [Embedding in a Host](../guides/embedding-in-a-host) |

```typescript
// Auto-connect (the npm-consumer default)
import { createRuntimeClient } from '@taucad/runtime';
import { presets } from '@taucad/runtime/presets';
import { fromMemoryFs } from '@taucad/runtime/filesystem';
import { inProcessTransport } from '@taucad/runtime/transport/in-process';

const runtime = presets.all();
const client = createRuntimeClient({
  transport: inProcessTransport({ runtime, fileSystem: fromMemoryFs() }),
});
const result = await client.export('glb', {
  source: { files: { 'main.ts': 'export default () => {}' } },
});
```

```typescript
// Explicit connect (host-wiring scenarios)
import { createRuntimeClient } from '@taucad/runtime';
import type { runtime } from './runtime.worker';
import { webWorkerTransport } from '@taucad/runtime/transport/web';
import { openFileSystemBridge } from '@taucad/fs-bridge';
import { fromFileSystemBridge } from '@taucad/runtime/filesystem';

const fsWorker = new Worker(new URL('./fm-worker.ts', import.meta.url));
const fsBridge = openFileSystemBridge(fsWorker);
const filePool = new SharedArrayBuffer(64 * 1024 * 1024);

// `filePoolBuffer` is the ONLY SharedArrayBuffer the public API exposes —
// geometry-pool and abort-channel SABs are allocated and owned internally
// by the active transport.
const client = createRuntimeClient<typeof runtime>({
  transport: webWorkerTransport({
    createWorker: () => new Worker(new URL('./runtime.worker.ts', import.meta.url), { type: 'module' }),
    fileSystem: fromFileSystemBridge(fsBridge),
    filePoolBuffer: filePool,
  }),
});
await client.connect();

// ...drive the runtime as usual; on shutdown:
client.terminate();
fsBridge.dispose();
```

## Usage

`client.export(format, input)` runs a single render-and-export cycle and returns a Promise:

```typescript
import { createRuntimeClient } from '@taucad/runtime';
import { presets } from '@taucad/runtime/presets';
import { fromMemoryFs } from '@taucad/runtime/filesystem';
import { inProcessTransport } from '@taucad/runtime/transport/in-process';

const runtime = presets.all();
const client = createRuntimeClient({
  transport: inProcessTransport({ runtime, fileSystem: fromMemoryFs() }),
});

const result = await client.export('glb', {
  source: { files: { 'main.ts': 'export default () => {}' } },
});

if (result.success) {
  console.log(`Exported ${result.data.bytes.byteLength} bytes`);
}

client.terminate();
```

For UI viewers that need to react to parameter changes or file edits, use the autonomous render loop documented in [Live Rendering](../guides/live-rendering) -- `client.render`, `client.updateParameters`, `client.setOptions`, and the `geometry` event.
