# Filesystem API

Use the filesystem API when configuring how kernels read and write project files. The package provides constructors for Node.js, browser directory handles, in-memory and already-confined fs-compatible backends, plus bridge utilities for cross-worker filesystem access.

## Constructors

| Function                        | Import Path                          | Description                                               |
| ------------------------------- | ------------------------------------ | --------------------------------------------------------- |
| `fromNodeFs(basePath)`          | `@taucad/runtime/filesystem/node`    | Node.js filesystem rooted at `basePath`                   |
| `fromBrowserFs(root)`           | `@taucad/runtime/filesystem/browser` | Browser directory handle exposed as runtime `/`           |
| `fromMemoryFs(files?)`          | `@taucad/runtime/filesystem`         | In-memory Map-backed filesystem, optionally seeded        |
| `fromFsLike(fs)`                | `@taucad/runtime/filesystem`         | An already-confined virtual filesystem                    |
| `fromFileSystemBridge(open)`    | `@taucad/runtime/filesystem`         | A fresh rooted bridge connection for each runtime binding |
| `createRuntimeFileSystem(base)` | `@taucad/runtime/filesystem`         | Wrap `RuntimeFileSystemBase` with enhanced helper methods |

Every constructor establishes the root of the [runtime-path namespace](../concepts/path-namespaces). Filesystem method arguments such as `/main.ts` refer to that supplied root, not the host operating system's root.

## Bridge Utilities

For cross-worker filesystem access, these utilities create MessagePort-based bridges:

| Function                                       | Description                                                                                                                                                                                 |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `createBridgePort(handlers)`                   | Generic `@taucad/rpc/bridge` helper: serve handlers in-process; returns **`BridgePort`** with a raw **`MessagePort`** for `postMessage(..., [port])` transfer to a callee worker.           |
| `createBridgeServer(handlers, port, options?)` | Serve an object's methods over a `Port` adapter (`wrapMessagePort` when using bare `MessagePort`).                                                                                          |
| `createBridgeProxy<T>(port)`                   | Proxy client over a **`Port`** (never a bare transferred **`MessagePort`** without **`wrapMessagePort`**).                                                                                  |
| `createBridgeCall(port, method, args)`         | Lower-level RPC triple over a **`Port`**.                                                                                                                                                   |
| `exposeFileSystem(handlers, options?)`         | `@taucad/fs-bridge` worker-side listener for incoming filesystem bridge ports.                                                                                                              |
| `openFileSystemBridge(worker, options?)`       | `@taucad/fs-bridge` client side: opens a **`MessageChannel`**, transfers one end to an FS-owning worker, and returns a raw filesystem bridge connection for runtime or another worker.      |
| `createFileSystemBridge(worker, options?)`     | `@taucad/fs-bridge` client side: opens a **`MessageChannel`**, transfers one end to an FS-owning worker. Returns **`FileSystemBridge`** with a wrapped **`Port`** for same-isolate proxies. |
| `catchMessages(port, handler)`                 | Buffer messages during initialization.                                                                                                                                                      |
| `extractTransferables(value)`                  | Collect **`ArrayBuffer`** transferables for **`postMessage`**.                                                                                                                              |

## Usage

### Node.js Filesystem

```typescript
import { createRuntimeClient } from '@taucad/runtime';
import { fromNodeFs } from '@taucad/runtime/filesystem/node';
import { inProcessTransport } from '@taucad/runtime/transport/in-process';
import { defineRuntime } from '@taucad/runtime/worker';
import { replicad } from '@taucad/runtime/kernels';
import { esbuild } from '@taucad/runtime/bundler';

const runtime = defineRuntime({
  kernels: [replicad()],
  bundlers: [esbuild()],
});

const client = createRuntimeClient({
  transport: inProcessTransport({ runtime, fileSystem: fromNodeFs('/path/to/project') }),
});
```

### In-Memory Filesystem

```typescript
import { createRuntimeClient } from '@taucad/runtime';
import { fromMemoryFs } from '@taucad/runtime/filesystem';
import { inProcessTransport } from '@taucad/runtime/transport/in-process';
import { defineRuntime } from '@taucad/runtime/worker';
import { replicad } from '@taucad/runtime/kernels';
import { esbuild } from '@taucad/runtime/bundler';

const runtime = defineRuntime({
  kernels: [replicad()],
  bundlers: [esbuild()],
});

const client = createRuntimeClient({
  transport: inProcessTransport({
    runtime,
    fileSystem: fromMemoryFs({
      '/main.ts': 'export default function main() { return null; }',
    }),
  }),
});
```

### Filesystem Bridge

Trusted host code selects an authority route once and supplies a connection factory. The runtime sees only the rooted project's writable local namespace:

```typescript
import { fromFileSystemBridge, openFileSystemBridge } from '@taucad/runtime/filesystem';

const fileSystem = fromFileSystemBridge(() => openFileSystemBridge(fileManagerWorker, { root: '/projects/widget' }));
```

Inside runtime, `/main.ts`, `/.tau/cache/**`, and `/node_modules/**` all belong to that project. The runtime receives no project id or authority-global root and performs no authorization checks; filesystem reachability is the authority boundary. `fromFsLike(fs)` follows the same local-path contract but assumes `fs` is already confined. Use `fromNodeFs(hostRoot)` for raw Node.js access so the adapter can enforce lexical and symlink containment.
