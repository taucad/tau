# Kernel Plugins

Concrete kernels ship in their own packages. Each package declares a package-named toolkit factory, re-exports that binding as `plugin` for mechanical loading, and exposes a role-named kernel factory for direct authoring and isolated tests.

## Packages

| Package                      | Kernel ID            | Extensions                           | Role factory              |
| ---------------------------- | -------------------- | ------------------------------------ | ------------------------- |
| `@taucad/replicad`           | `replicad`           | `ts`, `js`                           | `replicadKernel`          |
| `@taucad/opencascade`        | `opencascade`        | `ts`, `js`                           | `opencascadeKernel`       |
| `@taucad/manifold`           | `manifold`           | `ts`, `js`                           | `manifoldKernel`          |
| `@taucad/jscad`              | `jscad`              | `ts`, `js`                           | `jscadKernel`             |
| `@taucad/openrscad`          | `openrscad`          | `scad`                               | `openrscadKernel`         |
| `@taucad/zoo`                | `zoo`                | `kcl`                                | `zooKernel`               |
| `@taucad/gltf`               | `gltf`               | `glb`, `gltf`                        | `gltfKernel`              |
| `@taucad/brep`               | `brep`               | `step`, `stp`, `iges`, `igs`, `brep` | `brepKernel`              |
| `@taucad/rhino`              | `rhino`              | `3dm`                                | `rhinoKernel`             |
| `@taucad/assimp`             | `assimp`             | Explicit mesh/scene formats          | `assimpKernel`            |
| `@taucad/opencascade-native` | `opencascade-native` | `ts`, `js`                           | `opencascadeNativeKernel` |
| `@taucad/openrscad-native`   | `openrscad`          | `scad`                               | `openrscadNativeKernel`   |

No first-party kernel uses `'*'`. Import formats are owned by explicit backend kernels.

The two native packages target Node hosts and remain outside the first release until their platform artifacts are publishable. Register either OpenRSCAD implementation, not both: they intentionally share the `openrscad` capability ID.

## Toolkit composition

```typescript
import { defineRuntime } from '@taucad/runtime/worker';
import { esbuild } from '@taucad/esbuild';
import { replicad } from '@taucad/replicad';

export const runtime = defineRuntime({ plugins: [esbuild(), replicad()] });
```

## Configured composition

Configure a packaged kernel through its toolkit. Reserve direct buckets for app-local capabilities, isolated kernel tests, or whole-role ordering outside plugin expansion:

```typescript
import { defineRuntime } from '@taucad/runtime/worker';
import { esbuild } from '@taucad/esbuild';
import { replicad } from '@taucad/replicad';

export const runtime = defineRuntime({
  plugins: [esbuild(), replicad({ kernels: { default: { wasm: 'auto' } } })],
});
```

Backends load in the selected kernel's `initialize()` and live in its context. Toolkit namespaces never rewrite flat capability IDs.
