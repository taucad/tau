# Transport API

Most applications use a topology-specific high-level helper. Browser apps pair `createWebWorkerClientOptions()` with `serveWebWorkerRuntime()`, while Electron renderers use `createElectronClientOptions()`. Use the raw transport factories when binding a custom filesystem or host, and use `@taucad/runtime/transport` only when authoring a new transport.

```typescript
import { createRuntimeClient } from '@taucad/runtime/client';
import { createWebWorkerClientOptions } from '@taucad/runtime/transport/web';

const clientOptions = createWebWorkerClientOptions({
  createWorker: () => new Worker(new URL('./runtime.worker.ts', import.meta.url), { type: 'module' }),
});

const client = createRuntimeClient(clientOptions);
```

Concrete topology imports remain isolated:

```typescript
import { webWorkerTransport } from '@taucad/runtime/transport/web';
import { nodeWorkerTransport } from '@taucad/runtime/transport/node';
import { inProcessTransport } from '@taucad/runtime/transport/in-process';
import { webSocketTransport } from '@taucad/runtime/transport/websocket';
```

The low-level Node transport requires the application-owned worker entry URL. `createNodeClient()` remains the zero-configuration in-process helper for command-line and server workloads.

```typescript
import { nodeWorkerTransport } from '@taucad/runtime/transport/node';

const transport = nodeWorkerTransport({
  url: new URL('./runtime.worker.ts', import.meta.url),
});
```

## Remote hosts over WebSockets

`webSocketTransport` dials a kernel host in another process or on another machine. The client half is browser-safe; the Node server half ships separately at `@taucad/runtime/transport/websocket-host` so `ws` and `node:http` never reach a browser graph.

```typescript
import type { AnyRuntimeDefinition } from '@taucad/runtime/worker';
import { createRuntimeWorker } from '@taucad/runtime/worker';
import { fromNodeFs } from '@taucad/runtime/filesystem/node';
import { webSocketHost } from '@taucad/runtime/transport/websocket-host';

declare const runtime: AnyRuntimeDefinition;

const host = webSocketHost({
  worker: () => createRuntimeWorker({ runtime }),
  fileSystem: fromNodeFs('/srv/projects/demo'),
  allowedOrigins: ['https://app.example.com'],
  host: '0.0.0.0', // defaults to 127.0.0.1, which a remote browser cannot reach
  port: 8080,
});
await host.ready;
```

```typescript
import { createRuntimeClient } from '@taucad/runtime/client';
import { webSocketTransport } from '@taucad/runtime/transport/websocket';

const client = createRuntimeClient({
  transport: webSocketTransport({ url: 'ws://127.0.0.1:8080' }),
});
```

The host serves one kernel worker per connection, so two clients never collide. The descriptor is `{ id: 'web-socket', wire: 'remote', memory: { geometryDelivery: 'copy', abortSignal: 'wire-notify' }, fileSystem: 'host-local' }` — a socket carries neither transferables nor a `SharedArrayBuffer`.

Pass a `fileSystem` on the **client** instead (and start the host without one) to keep the project on the consumer's side. The transport then opens a second socket, `/fs`, on which the consumer is the bridge server: the remote kernel reads, writes and watches through it, and the descriptor reports `fileSystem: 'bridged'`. There is no multiplexer; the two sockets are correlated by a transport-private session id.

```typescript
import { createRuntimeClient } from '@taucad/runtime/client';
import { fromMemoryFs } from '@taucad/runtime/filesystem';
import { webSocketTransport } from '@taucad/runtime/transport/websocket';

const client = createRuntimeClient({
  transport: webSocketTransport({
    url: 'ws://127.0.0.1:8080',
    fileSystem: fromMemoryFs(),
  }),
});
```

`allowedOrigins` is an exact-match allowlist enforced at the HTTP upgrade; a request with no `Origin` header (any Node client) is admitted, so the default `[]` denies every browser. The host also pings idle peers and drops the ones that stop answering. Remote hosts are bound to the same build — the wire hello carries `protocolVersion` and a mismatch is rejected at connect.

### Sharing an HTTP server, authorizing an upgrade, bounding a frame

Pass `server` to attach to an HTTP (or HTTPS) server you already run, and `pathPrefix` to move both routes under a path. Matching is exact — `${pathPrefix}/runtime` and `${pathPrefix}/fs` — and on a server the host does not own every other upgrade is **ignored**, so another `WebSocketServer` on the same server keeps its own paths in either registration order. A host that owns its server still answers an unknown path with a raw `404`.

`authorize` runs after the origin check and before the upgrade completes. Returning `false` or throwing refuses the upgrade with a raw `401`. There is no client→server hello frame, so a credential travels on the URL or in `Sec-WebSocket-Protocol`; the client's `url` search params are preserved on both sockets, so `webSocketTransport({ url: 'ws://127.0.0.1:8080/?token=…' })` reaches the hook unchanged.

```typescript
import type { Server } from 'node:http';
import type { AnyRuntimeDefinition } from '@taucad/runtime/worker';
import { createRuntimeWorker } from '@taucad/runtime/worker';
import { webSocketHost } from '@taucad/runtime/transport/websocket-host';

declare const runtime: AnyRuntimeDefinition;
declare const server: Server;
declare const isPaired: (token: string | null) => boolean;

const host = webSocketHost({
  worker: () => createRuntimeWorker({ runtime }),
  server, // shared with the rest of the application
  pathPrefix: '/rt', // serves /rt/runtime and /rt/fs
  authorize: (request) => isPaired(new URL(request.url ?? '/', 'http://localhost').searchParams.get('token')),
  maxPayload: 32 * 1024 * 1024,
});
await host.ready;
```

`maxPayload` is the per-frame ceiling in bytes, defaulting to `ws`'s 100 MiB. There is no chunking or streaming sub-protocol, so one frame carries one whole message — a `readFile` result over the ceiling is never delivered and the socket closes with `1009`, which the client settles as `wire-failure`. Raise it for large binary assets, or keep the default.

The author subpath exports `defineRuntimeTransport`, `runtimeProtocolSchemas`, and the shared client/host contracts:

```typescript
import { defineRuntimeTransport, runtimeProtocolSchemas } from '@taucad/runtime/transport';
import type {
  RuntimeTransportClient,
  RuntimeTransportCloseResult,
  RuntimeTransportPreviewReservation,
  RuntimeTransportRenderTarget,
  RuntimeTransportTimeoutRecovery,
} from '@taucad/runtime/transport';
```

## Preview admission

`RuntimeTransportClient.reservePreview()` runs synchronously before source staging or other asynchronous admission work. A SAB-backed transport advances its internal abort generation and returns the exact captured value:

The implementation below advances an internal generation and returns it from `reservePreview`.

A wire-only transport returns an empty reservation:

A wire-only transport instead returns an empty reservation from `reservePreview`.

The reservation is opaque. Do not derive render ordering from it, reuse it for another preview, or allocate a second generation when the command is sent.

## Timeout recovery

An isolated transport reports `kind: 'terminable'`. `abortRender` must target exactly the supplied render; `terminate` must terminate only this client's host and settle `closed` with the timeout cause:

The complete implementation below forwards the exact target to its host and settles closure after termination.

`renderId` and `abortGeneration` are opaque correlation values. Forward them unchanged. A delayed timeout for one ID must never cancel its successor.

A same-isolate transport reports unsupported recovery:

A same-isolate implementation uses `{ kind: 'unsupported' }` instead.

Do not advertise a terminable timeout based on a diagnostic descriptor or the presence of `SharedArrayBuffer`. The capability is behavioral: the transport must be able to stop an unresponsive host from another event loop or process.

## Typed closure

`RuntimeTransportClient.closed` resolves once with the first terminal cause and never rejects:

The complete implementation below uses an explicit promise resolver so the example typechecks under the documentation harness's default library.

| Cause            | When to use                                                         |
| ---------------- | ------------------------------------------------------------------- |
| `requested`      | Consumer called normal close/terminate                              |
| `render-timeout` | Bounded timeout recovery terminated this client's isolated host     |
| `host-exit`      | Worker or process exited independently; include `exitCode` if known |
| `wire-failure`   | Native channel failed; include the original `Error`                 |

First-cause ownership matters. A later requested close must not overwrite an already observed host exit, wire failure, or timeout termination.

## Complete client contract

A materialized `RuntimeTransportClient` combines the cancellation members with the normal lifecycle and delivery methods:

```typescript
import type {
  RuntimeTransportClient,
  RuntimeTransportCloseResult,
  RuntimeTransportPreviewReservation,
  RuntimeTransportRenderTarget,
  RuntimeTransportTimeoutRecovery,
} from '@taucad/runtime/transport';

let generation = 0;
const reservePreview = (): RuntimeTransportPreviewReservation => ({ abortGeneration: ++generation });

let resolveClosed: (result: RuntimeTransportCloseResult) => void = () => {};
const closed = new Promise<RuntimeTransportCloseResult>((resolve) => {
  resolveClosed = resolve;
});
let closedResult: RuntimeTransportCloseResult | undefined;
const settleClosed = (result: RuntimeTransportCloseResult): void => {
  if (closedResult) return;
  closedResult = result;
  resolveClosed(result);
};

const sendTargetedTimeoutToHost = (_target: RuntimeTransportRenderTarget): void => {};
const terminateExactHost = async (): Promise<void> => {};
const timeoutRecovery: RuntimeTransportTimeoutRecovery = {
  kind: 'terminable',
  abortRender(target) {
    sendTargetedTimeoutToHost(target);
  },
  async terminate() {
    await terminateExactHost();
    settleClosed({ cause: 'render-timeout' });
  },
};

const transportClient: RuntimeTransportClient = {
  id: 'my-isolated-host',
  closed,
  reservePreview,
  renderTimeoutRecovery: timeoutRecovery,
  describe: () => ({
    id: 'my-isolated-host',
    wire: 'web-worker',
    memory: { geometryDelivery: 'transfer', abortSignal: 'wire-notify' },
    fileSystem: 'unbound',
  }),
  async open() {
    throw new Error('Open the transport wire here.');
  },
  async initialize() {
    throw new Error('Send the runtime initialization call here.');
  },
  async resolveGeometry() {
    throw new Error('Decode the transported geometry here.');
  },
  async close() {
    settleClosed({ cause: 'requested' });
  },
};
```

`close()` must be idempotent and must terminate the exact host owned by this materialized client. `createRuntimeClient` observes `closed` from construction onward, so a failure before or during `open()` still settles admitted work.

Use `runtimeProtocolSchemas` at both channel boundaries. It rejects malformed timeout reasons, missing target identities, and invalid generations before they reach `KernelWorker`.
