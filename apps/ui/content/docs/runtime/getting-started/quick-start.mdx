# Quick Start

Render a 3D model from TypeScript code using the Replicad kernel. You will install the package, create a runtime client, and render geometry to glTF.

## Prerequisites

- Node.js 20 or later
- A package manager: npm, pnpm, or yarn

## Install

```bash tab="pnpm"
pnpm add @taucad/runtime @taucad/replicad @taucad/esbuild
```

```bash tab="npm"
npm install @taucad/runtime @taucad/replicad @taucad/esbuild
```

```bash tab="yarn"
yarn add @taucad/runtime @taucad/replicad @taucad/esbuild
```

For framework-specific configuration (Vite, Node.js), see [Installation](./installation).

## Render a 3D Model

Create a file called `render.ts` and paste the following code:

```typescript
import { defineRuntime } from '@taucad/runtime';
import { createNodeClient } from '@taucad/runtime/node';
import { esbuild } from '@taucad/esbuild';
import { replicad } from '@taucad/replicad';

const runtime = defineRuntime({ plugins: [esbuild(), replicad()] });
const client = await createNodeClient(undefined, { runtime });
const result = await client.export('glb', {
  source: {
    files: { 'main.ts': 'import { makeBaseBox } from "replicad";\nexport default () => makeBaseBox(30, 50, 10);' },
  },
});
if (!result.success) throw new Error(`Export failed: ${result.issues[0]?.message}`);
console.log(`Exported ${result.data[0].name}: ${result.data[0].bytes.byteLength} bytes`);
client.terminate();
```

The application owns this runtime definition. `createNodeClient` supplies the in-process transport and, with no project path, an in-memory filesystem; inline `source.files` input is staged into it and the first command call starts the selected capabilities.

### How the runtime is wired

A `RuntimeClient` is composed of three orthogonal plug points. `createNodeClient` is a Node convenience that fills the last two for you:

| Plane          | What it owns                                                                         | Supplied above                               |
| -------------- | ------------------------------------------------------------------------------------ | -------------------------------------------- |
| **Runtime**    | Executable kernels, middleware, bundlers, and transcoders                            | your `defineRuntime` — Replicad + esbuild    |
| **Transport**  | The wire (`MessagePort` / in-process channel / Electron `MessagePortMain`)           | `inProcessTransport` (by `createNodeClient`) |
| **Filesystem** | The source of truth for files (`fromMemoryFs`, `fromNodeFs`, `fromFileSystemBridge`) | `fromMemoryFs()` (by `createNodeClient`)     |

Pass a directory instead of `undefined` — `createNodeClient('/path/to/project', { runtime })` — to read sources from disk with `source: { path: 'main.ts' }`.

The same plug points compose every supported topology — browser UI, in-process Node, Electron renderer + main, multi-window Electron — without core changes. See [Worker Model → Topology Recipes](../concepts/worker-model#topology-recipes) for the canonical T1–T4 configs.

Add further toolkit or role factories only when the application needs them:

```typescript
import { createRuntimeClient } from '@taucad/runtime';
import { defineRuntime } from '@taucad/runtime/worker';
import { replicad } from '@taucad/replicad';
import { esbuild } from '@taucad/esbuild';
import { inProcessTransport } from '@taucad/runtime/transport/in-process';

const runtime = defineRuntime({
  plugins: [replicad(), esbuild()],
});

const client = createRuntimeClient({
  transport: inProcessTransport({ runtime }),
});
```

## Expected Output

```
Exported model.glb: 5824 bytes (model/gltf-binary)
```

`result.data` is an ordered, non-empty array of export files. A GLB route normally returns one `model.glb`; dependent formats may return companions such as glTF + BIN or OBJ + MTL, so formats other than GLB are worth iterating:

```typescript
for (const file of result.data) {
  console.log(`Exported ${file.name}: ${file.bytes.byteLength} bytes (${file.mimeType})`);
}
```

Each file's `bytes` is a `Uint8Array` that you can write to disk, stream over HTTP, or hand to a compatible viewer. The exact byte count depends on the model and tessellation settings.
