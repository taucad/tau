# Capture Camera Views

`@taucad/image` can fit a model automatically or reproduce a complete camera sent by a viewer. Both paths use serializable camera objects, so the same request works in a worker, Node.js, or an RPC renderer.

## Choose framing

Use `framing: 'fit'` when nanoraster should place the camera from model bounds. Direction points from the bounds centre toward the camera. `up` controls the top of the image.

```ts
const fittedCamera = {
  framing: 'fit',
  direction: [1, -1, 0.7],
  up: [0, 0, 1],
  margin: 0.1,
  projection: { kind: 'perspective', verticalFieldOfView: 45 },
} as const;
```

Use `framing: 'fixed'` when the image must preserve position, target, roll, and magnification. Position, target, orthographic span, and clipping use the GLB world unit.

```ts
const fixedCamera = {
  framing: 'fixed',
  position: [0.09, -0.065, 0.045],
  target: [0.005, 0, 0.008],
  up: [0.16, 0.11, 0.98],
  projection: {
    kind: 'perspective',
    verticalFieldOfView: 48,
    zoom: 1.25,
  },
  clipping: { near: 0.0001, far: 2 },
} as const;
```

Perspective field of view is vertical and measured in degrees. Zoom is a positive magnification: the effective field of view is `2 × atan(tan(verticalFieldOfView / 2) / zoom)`. An orthographic projection uses `verticalSpan / zoom` as its effective visible span. A fixed camera's `up` vector is required because position and target alone cannot preserve roll.

Omit `clipping` to derive planes from model bounds. Set it only when the caller owns the scene depth range. Geometry at or behind the near plane is clipped; line segments crossing that plane are trimmed before screen-space expansion.

## Capture a live Three.js camera

Keep Three.js at the adapter boundary. `readThreeCameraState` copies world placement, roll, projection, zoom, clipping, and aspect into `@taucad/camera` data. `toNanorasterCamera` then converts camera lengths into the GLB unit.

```ts
import { readThreeCameraState } from '@taucad/three/camera';
import { toNanorasterCamera } from '@taucad/image/camera';

const cameraState = readThreeCameraState({
  camera,
  target: controls.target,
});

const width = 2400;
const height = Math.round(width / cameraState.aspect);
const capture = await client.export('webp', {
  source: { path: '/main.ts' },
  content: { includeEdges: true },
  exportOptions: {
    width,
    height,
    quality: 1,
    background: '#242424',
    label: 'main.ts',
    axes: true,
    scaleBar: true,
    camera: toNanorasterCamera({
      cameraState,
      lengthScale: 0.001, // viewer millimetres to GLB metres
    }),
  },
});
```

Use the same aspect for the output and source camera. A different output aspect deliberately changes horizontal composition. WebP `quality: 1` is lossless.

Copy camera state before awaiting geometry or network work. This makes the image represent the view at the moment the user requested capture, even if the viewer moves while rendering continues.

## Render editable presets

Each batch view owns its camera. A UI can bind inputs directly to these plain objects, then send the edited array to a local or remote renderer without mutating a shared camera.

```ts
const views = [
  {
    id: 'three-quarter',
    label: 'Three-quarter',
    camera: {
      framing: 'fit',
      direction: [1, -1, 0.7],
      up: [0, 0, 1],
      margin: 0.1,
      projection: { kind: 'perspective', verticalFieldOfView: 45 },
    },
  },
  {
    id: 'low-inspection',
    label: 'Low inspection',
    camera: {
      framing: 'fixed',
      position: [0.12, -0.08, 0.018],
      target: [0, 0, 0.012],
      up: [0, 0, 1],
      projection: { kind: 'perspective', verticalFieldOfView: 38, zoom: 1.15 },
    },
  },
  {
    id: 'plan',
    label: 'Plan',
    camera: {
      framing: 'fixed',
      position: [0, 0, 0.2],
      target: [0, 0, 0],
      up: [0, 1, 0],
      projection: { kind: 'orthographic', verticalSpan: 0.16, zoom: 1 },
    },
  },
] as const;

const captures = await client.export('webp', {
  source: { path: '/main.ts' },
  content: { includeEdges: true },
  exportOptions: {
    mode: 'batch',
    width: 1600,
    height: 1600,
    quality: 1,
    background: '#242424',
    axes: true,
    scaleBar: true,
    views,
  },
});
```

Fit framing has one magnification control: `margin`. Fixed perspective uses vertical field of view and zoom; fixed orthographic uses vertical span and zoom. Keeping those cases separate avoids competing fit and zoom rules.

## Send the request over RPC

Camera options contain JSON values only. Send the complete export request, not a renderer instance or a Three.js camera:

```ts
socket.send(
  JSON.stringify({
    id: crypto.randomUUID(),
    method: 'capture',
    params: {
      source: { path: '/main.ts' },
      format: 'webp',
      exportOptions: { mode: 'batch', width: 1600, height: 1600, views },
    },
  }),
);
```

Validate the request at the receiver before rendering. The image plugin schemas reject non-finite vectors, coincident position and target, collinear direction and up, invalid projection values, inverted clip planes, duplicate view IDs, and unknown fields.
