# Configure Render Timeouts

Use a render timeout when a preview must stop occupying an isolated runtime host after a fixed wall-clock deadline. The deadline applies independently to `render`, `updateParameters`, and render-affecting `setOptions` calls. It is not an export timeout.

## Prerequisites

- [Install @taucad/runtime](../getting-started/installation)
- [Live Rendering](./live-rendering)
- A Web Worker, Node Worker, or Electron utility-process transport

## What the timeout guarantees

When a deadline expires, the matching render Promise rejects immediately with `RenderTimeoutError`. Rejection does not wait for the worker to receive or acknowledge cancellation, so the guarantee also holds without `SharedArrayBuffer`.

The runtime then gives the isolated host a bounded recovery window:

1. The exact timed-out render receives cooperative cancellation.
2. New preview work is quarantined so it cannot overlap the timed-out operation.
3. If the host acknowledges cancellation, it is retained and the latest queued preview runs.
4. If the host remains blocked, only that client's host is terminated. Queued work rejects with `RuntimeTerminatedError` and `causeKind === 'render-timeout'`.

Supersession is unchanged: an older call resolves with `{ superseded: true }` when a newer public command or autonomous watched-filesystem preview takes ownership. Selected geometry arrives over the `geometry` event. Supersession is not a timeout or an exception.

## Browser worker setup

Keep the reusable options spec at module scope. Import the client and selected worker topology from their concrete subpaths:

```typescript
// runtime-client.ts
import { createRuntimeClient, isRenderTimeoutError } from '@taucad/runtime/client';
import { createWebWorkerClientOptions } from '@taucad/runtime/transport/web';

const clientOptions = createWebWorkerClientOptions({
  createWorker: () => new Worker(new URL('./runtime.worker.ts', import.meta.url), { type: 'module' }),
  renderTimeout: 60_000,
});

let client = createRuntimeClient(clientOptions);

export const renderModel = async (code: string) => {
  try {
    const outcome = await client.render({
      source: { files: { 'main.ts': code } },
    });

    if (outcome.superseded) return { kind: 'superseded' } as const;
    return { kind: 'rendered', geometry: outcome.geometry } as const;
  } catch (error) {
    if (isRenderTimeoutError(error)) {
      return { kind: 'timed-out', message: error.message } as const;
    }
    throw error;
  }
};
```

The worker entry owns executable plugins:

```typescript
// runtime.worker.ts
import { esbuild } from '@taucad/esbuild';
import { replicad } from '@taucad/replicad';
import { defineRuntime } from '@taucad/runtime/worker';
import { serveWebWorkerRuntime } from '@taucad/runtime/worker/web';

export const runtime = defineRuntime({
  plugins: [replicad(), esbuild()],
});

await serveWebWorkerRuntime({ runtime });
```

All temporal values are milliseconds. Zero disables the timeout.

## Change the deadline after connection

`setRenderTimeout` is synchronous, requires a connected client, and affects only previews admitted after the call. It never changes the captured deadline of an in-flight render.

```typescript
import { createRuntimeClient } from '@taucad/runtime';
import { fromMemoryFs } from '@taucad/runtime/filesystem';
import { defineRuntime } from '@taucad/runtime/worker';
import { replicad } from '@taucad/replicad';
import { inProcessTransport } from '@taucad/runtime/transport/in-process';

const runtime = defineRuntime({ plugins: [replicad()] });
const client = createRuntimeClient({
  transport: inProcessTransport({ runtime, fileSystem: fromMemoryFs() }),
});

await client.connect();

client.setRenderTimeout(120_000);
// Later previews now have a two-minute deadline.

client.setRenderTimeout(0);
// Later previews have no wall-clock deadline.
```

## Recover after a blocked host is terminated

An isolated host that cooperates remains usable. If it cannot acknowledge cancellation, the latest preview queued during recovery rejects with `RuntimeTerminatedError('render-timeout')`. Recreate the client from the same module-scope options spec and retry that preview:

```typescript
import { createRuntimeClient, isRuntimeTerminatedError } from '@taucad/runtime/client';
import { createWebWorkerClientOptions } from '@taucad/runtime/transport/web';

const clientOptions = createWebWorkerClientOptions({
  createWorker: () => new Worker(new URL('./runtime.worker.ts', import.meta.url), { type: 'module' }),
  renderTimeout: 60_000,
});
let client = createRuntimeClient(clientOptions);

export const renderWithHostRestart = async (input: Parameters<typeof client.render>[0]) => {
  try {
    return await client.render(input);
  } catch (error) {
    if (!isRuntimeTerminatedError(error) || error.causeKind !== 'render-timeout') {
      throw error;
    }

    client = createRuntimeClient(clientOptions);
    return client.render(input);
  }
};
```

Branch on the typed guard and `causeKind`, not the error message. The message is human-facing prose; the discriminants are the stable contract.

## Electron without SharedArrayBuffer

Electron renderer-to-utility cancellation uses a wire notification. Synchronous native or WASM work can prevent the utility process from reading that notification, so the Electron transport also owns an opaque host lease that lets the main process terminate exactly the blocked utility. Sibling runtime clients are not affected.

Use the renderer helper rather than requesting ports or handling host IDs yourself:

```typescript
// renderer/runtime-client.ts
import { createRuntimeClient } from '@taucad/runtime/client';
import { createElectronClientOptions } from '@taucad/runtime/electron/renderer';

const electronClientOptions = createElectronClientOptions({
  renderTimeout: 60_000,
});

export const createElectronRuntimeClient = async () => createRuntimeClient(await electronClientOptions());
```

Keep `electronClientOptions` at module scope. Each call requests a fresh utility-process port and a fresh host lease. The preload and main-process helpers release that lease on normal client termination and on hard timeout recovery.

## Same-isolate transports cannot enforce the deadline

Do not configure a non-zero timeout with `inProcessTransport`. The timer and kernel work share one event loop, so a synchronous block prevents the timer itself from running. This remains true even when `SharedArrayBuffer` exists.

Both a non-zero creation option and a later non-zero setter fail synchronously with an actionable `TypeError`:

```typescript
import { createRuntimeClient } from '@taucad/runtime/client';
import { fromMemoryFs } from '@taucad/runtime/filesystem';
import { defineRuntime } from '@taucad/runtime/worker';
import { replicad } from '@taucad/replicad';
import { inProcessTransport } from '@taucad/runtime/transport/in-process';

const runtime = defineRuntime({ plugins: [replicad()] });

// Throws: this topology cannot enforce a wall-clock render deadline.
createRuntimeClient({
  transport: inProcessTransport({ runtime, fileSystem: fromMemoryFs() }),
  renderTimeout: 1_000,
});
```

Use zero or omit the option for in-process execution. Choose a worker-backed topology when deadline enforcement is required.
