# @taucad/runtime

A multi-kernel CAD runtime for browser and Node.js. Run multiple CAD engines from a single, unified API with middleware support, automatic kernel selection, autonomous rendering, and Web Worker isolation.

```typescript
import { createRuntimeClient } from '@taucad/runtime';
import { defineRuntime } from '@taucad/runtime/worker';
import { replicad } from '@taucad/replicad';
import { fromMemoryFs } from '@taucad/runtime/filesystem';
import { inProcessTransport } from '@taucad/runtime/transport/in-process';

const runtime = defineRuntime({ plugins: [replicad()] });
const client = createRuntimeClient({
  transport: inProcessTransport({ runtime, fileSystem: fromMemoryFs() }),
});

const result = await client.export('step', {
  source: {
    files: {
      'box.ts': `
      import { makeBaseBox } from 'replicad';
      export default function main() {
        return makeBaseBox(10, 20, 30);
      }
    `,
    },
  },
});

// result.data -> { name: 'box.step', bytes: Uint8Array, mimeType: 'model/step' }
```

Or configure individual plugins for tree-shaking:

```typescript
import { createRuntimeClient } from '@taucad/runtime';
import { defineRuntime } from '@taucad/runtime/worker';
import { replicad } from '@taucad/replicad';
import { esbuild } from '@taucad/esbuild';
import { inProcessTransport } from '@taucad/runtime/transport/in-process';

const runtime = defineRuntime({
  plugins: [replicad(), esbuild()],
});

const client = createRuntimeClient({
  transport: inProcessTransport({ runtime }),
});
```

## Supported Kernels

| Kernel          | Language      | Strengths                                                                                                                         |
| --------------- | ------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| **Replicad**    | TypeScript/JS | Parametric BRep modeling via OpenCASCADE. STEP export.                                                                            |
| **OpenCASCADE** | TypeScript/JS | Direct OpenCASCADE API access. Full BRep control.                                                                                 |
| **Manifold**    | TypeScript/JS | Robust mesh booleans with `manifold-3d`. Fast WASM workflows.                                                                     |
| **OpenRSCAD**   | OpenSCAD      | Rust/Wasm implementation of the OpenSCAD language for browser workers, Node, and the CLI in [`@taucad/openrscad`](./api/kernels). |
| **JSCAD**       | TypeScript/JS | Parametric CSG with `@jscad/modeling`.                                                                                            |
| **Zoo (KCL)**   | KCL           | Cloud-native CAD with AI integration via Zoo API.                                                                                 |
| **glTF**        | glTF/GLB      | Mesh import and glTF/GLB transcoding via `@taucad/gltf`.                                                                          |
| **BRep**        | STEP/IGES     | BRep import through the `brep` kernel from `@taucad/brep`.                                                                        |
| **Rhino**       | 3DM           | Rhino import through `@taucad/rhino`.                                                                                             |
| **Assimp**      | Mesh formats  | Assimp-backed imports and transcodes through `@taucad/assimp`.                                                                    |

## Key Capabilities

- **Multi-kernel runtime** -- Switch between CAD engines based on file type or explicit selection.
- **Autonomous rendering** -- `render` and `updateParameters` hand the worker a `(source, parameters)` pair and let it own the render loop with file watching, debounced re-renders, and event-driven geometry push.
- **Cancellation without exceptions** -- When a newer public command or autonomous watched-filesystem preview takes ownership, the older call resolves with `{ superseded: true }` instead of throwing. Selected geometry arrives over the `geometry` event. Real failures (timeouts, kernel crashes, lifecycle errors) still throw typed errors, so `try/catch` only fires for genuine problems.
- **Plugin architecture** -- Extend with custom kernels, middleware, and bundlers via [`defineKernel`](./api/kernels), [`defineMiddleware`](./api/middleware), and [`defineBundler`](./api/bundler).
- **Middleware pipeline** -- Add caching, coordinate transforms, and edge detection with an onion-model middleware system.
- **Web Worker isolation** -- All kernel computation runs in Web Workers with MessagePort-based communication and a transport-owned cooperative-abort channel (backed by `SharedArrayBuffer` on SAB-capable transports).
- **Render cancellation** -- Abort in-progress renders instantly via cooperative proxy abort, async boundary checks, and generation counters.
- **Filesystem abstraction** -- Use Node.js fs, in-memory, or browser-based filesystems interchangeably.
- **TypeScript bundling** -- Built-in esbuild integration for JS/TS kernel inputs.
- **Framework integrations** -- Version-neutral Vite, React Router, Next.js, and Electron config helpers own required assets, headers, workers, and host-process boundaries.

## Part of the Tau Ecosystem

`@taucad/runtime` is the CAD runtime that powers [Tau](https://tau.new), the AI-powered CAD platform. The package is designed for standalone use -- you can integrate it into any JavaScript application without the Tau editor.

The Tau ecosystem also includes:

- **Tau Editor** -- A web-based CAD editor with AI-assisted modeling (documentation coming soon)
- **Tau Platform** -- Cloud infrastructure for CAD collaboration (documentation coming soon)
