## Reading the status

| Status          | Meaning                                                                                                                      |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **Complete**    | Implemented at the explicitly audited source revision, within the stated limits. Does not imply released to npm or deployed. |
| **Partial**     | A useful subset is implemented; the missing portion is named.                                                                |
| **In progress** | Implementation exists on an active branch or in unmerged work; acceptance/integration remains open.                          |
| **Planned**     | A linked design exists, but the capability is not integrated. A successful spike alone stays planned.                        |
| **Absent**      | No Tau adapter/authoring path found. This is a parity gap, not an approved implementation commitment.                        |
| **Unverified**  | Upstream/import behavior may exist, but the reviewed evidence does not establish Tau support.                                |

**GLB is the common 3D delivery baseline:** all 15 integrated kernel definitions declare GLB export. Native export below means a kernel's own runtime export route, including WASM/cloud implementations; it does not mean machine-code execution. An upstream library's other serializers do not automatically become Tau export routes.

### Conversion is a separate capability

The shared [Assimp transcoder](../../packages/plugins/assimp/src/assimp.transcoder.ts) adds registered routes from GLB/glTF to mesh formats, including formats such as STL/OBJ/3MF where available in the installed registry. PNG capture and slicing are separate plugins. Discover the configured runtime's routes rather than copying an upstream format list.

- JSCAD can reach STL through conversion; its kernel still declares only GLB.
- A mesh-to-STEP conversion does **not** grant exact BRep support.
- Conversion may lose materials, names, hierarchy, topology or mechanism metadata. An export appearing in a menu does not prove round-trip parity.

## Material / PBR parity

This table measures **author control and preservation in delivered GLB**, not whether the viewer happens to use a PBR shader. Every colored mesh can be displayed with default lighting; that does not make every kernel a full material authoring API.

**Full** means Tau's implemented glTF material baseline: core factors/maps, alpha/double-sidedness and supported physical extensions. The supported physical set is anisotropy, clearcoat, dispersion, emissive strength, IOR, iridescence, sheen, specular, transmission, volume and unlit. It does not mean every experimental glTF extension or identical pixels on every renderer. **Partial** means authored metallic/roughness with a smaller surface. **None** means no authored PBR controls; color/opacity or fixed shading may still work.

### Remaining parity gaps

- **Materials:** full supported PBR for Replicad/SMLib/PicoGK/PicoVoxel; SMLib UVs are box-projected. Build123d PR #708 adds qualified native PBR/textures, with complete extension parity unclaimed. OpenSCAD/JSCAD are color-only; Manifold/Zoo/OpenCascade remain partial; tscircuit has generated appearance.
- **Motion:** Replicad/SMLib/PicoGK/PicoVoxel share Tau mechanisms. Build123d PR #708 has a qualified native-joint bridge with shared playback; OpenSCAD/JSCAD/Manifold/Zoo/OpenCascade/tscircuit lack one. No STEP exporter is qualified for interoperable mechanism animation.
- **Structure:** Replicad Part/Assembly remains planned; SMLib/PicoGK/PicoVoxel/JSCAD/OpenCascade lack authorable hierarchy. Build123d PR #708 qualifies independent reusable native assemblies and descendant joints; cross-kernel warehouse publication remains separate. OpenSCAD scene attribution and Manifold’s node graph retain narrower guarantees than reusable engineering occurrences.
- **Identity:** names improve hover/selection; stable semantic identity through edits, kernel switches and vendor round trips remains an unqualified research proposal.
- **Physical/reuse:** authored density, exact geometry and ordinary snapshots exist (SMLib accepts `density` but STEP does not carry it); cross-kernel mass/provenance, published native reuse and large-assembly acceptance remain producer-specific or branch work. OpenCascade’s unit repair does not qualify Replicad’s engine.
- **Availability:** PicoGK remains desktop macOS arm64; Build123d requires a trusted provisioned native host; Zoo supports local hosts but runs cloud geometry. Native OpenCascade was removed (86c97d8370 / #329), so it is not an available parity target.
