Last audited **2026-10-01**, against `geospec` at `a9c781e4f`, which integrates `codex/picogk-full-pbr`, including PicoGK feature `49c8054c8` and PicoVoxel feature `dd714d74d`. ## Reading the status

| Status          | Meaning                                                                                                              |
| --------------- | -------------------------------------------------------------------------------------------------------------------- |
| **Complete**    | Implemented on the audited `geospec` baseline, within the stated limits. Does not imply released to npm or deployed. |
| **Partial**     | A useful subset is implemented; the missing portion is named.                                                        |
| **In progress** | Implementation exists on an active branch or in unmerged work; acceptance/integration remains open.                  |
| **Planned**     | A linked design exists, but the capability is not integrated. A successful spike alone stays planned.                |
| **Absent**      | No Tau adapter/authoring path found. This is a parity gap, not an approved implementation commitment.                |
| **Unverified**  | Upstream/import behavior may exist, but the reviewed evidence does not establish Tau support.                        |

**GLB is the common 3D delivery baseline:** all 14 integrated kernel definitions declare GLB export. Native export below means a kernel's own runtime export route, including WASM/cloud implementations; it does not mean machine-code execution. An upstream library's other serializers do not automatically become Tau export routes.

### Conversion is a separate capability

The shared [Assimp transcoder](../../packages/plugins/assimp/src/assimp.transcoder.ts) adds registered routes from GLB/glTF to mesh formats, including formats such as STL/OBJ/3MF where available in the installed registry. PNG capture and slicing are separate plugins. Discover the configured runtime's routes rather than copying an upstream format list.

- JSCAD can reach STL through conversion; its kernel still declares only GLB.
- A mesh-to-STEP conversion does **not** grant exact BRep support.
- Conversion may lose materials, names, hierarchy, topology or mechanism metadata. An export appearing in a menu does not prove round-trip parity.

## Material / PBR parity

This table measures **author control and preservation in delivered GLB**, not whether the viewer happens to use a PBR shader. Every colored mesh can be displayed with default lighting; that does not make every kernel a full material authoring API.

**Full** means Tau's implemented glTF material baseline: core factors/maps, alpha/double-sidedness and supported physical extensions. The supported physical set is anisotropy, clearcoat, dispersion, emissive strength, IOR, iridescence, sheen, specular, transmission, volume and unlit. It does not mean every experimental glTF extension or identical pixels on every renderer. **Partial** means authored metallic/roughness with a smaller surface. **None** means no authored PBR controls; color/opacity or fixed shading may still work.

| PicoGK                  | **Full — Complete**                    | `PicoGK.Material` overload: core factors/maps, alpha/double-sidedness, eleven supported physical extensions; legacy overload retained                    | Integrated into `geospec` at `a9c781e4f`. The [adapter](../../packages/plugins/picovoxel/src/picovoxel.kernel.ts) restores snapshot labels through the same shared naming convention. Reordering output may change fallback labels and payload-local IDs.
