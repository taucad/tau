# Geometry Naming Policy

Internal reference for naming geometry payloads emitted by Tau runtime kernels, converter boundaries, shared GLB/OFF utilities, and component-manifest-facing metadata.

## Rationale

Tau kernels produce names that are both user-visible labels and machine-addressable references. When a material name, scene name, component ID, selector, native handle name, or export filename is generated independently by each kernel, the explorer and chat references expose inconsistent semantics. This policy separates display labels from identity and provenance so new kernels do not copy legacy fallback strings.

## Rules

### 1. Preserve Authored and Imported Names

Preserve non-empty names authored by user code or present in user-imported GLB/glTF payloads unless a boundary has explicit provenance that the name was generated by Tau or a converter.

**Why**: A user can intentionally name a material `Material_Default` or a scene `Scene`; the same string is only rewriteable when Tau knows it generated the label.

CORRECT:

```typescript
resolveMaterialName({ name: importedMaterialName, source: 'imported' });
```

INCORRECT:

```typescript
if (material.getName() === 'Material_Default') material.setName('');
```

### 2. Generate Shape Display Labels Centrally

Use `formatShapeName()`, `resolveShapeName()`, and `uniqueShapeName()` from `packages/runtime/src/utils/shape-names.ts` for Tau-owned unnamed shape display labels. The generated fallback format is one-indexed: `Shape 1`, `Shape 2`, etc.

**Why**: Shape labels appear in GLB node/mesh names, diagnostics, native handles, topology names, and per-shape exports; local fallback strings drift.

CORRECT:

```typescript
const label = resolveShapeName({ index, name: candidateName, source: 'generated' });
```

INCORRECT:

```typescript
const label = candidateName ?? `Shape_${index}`;
```

### 3. Keep Semantic Node and Mesh Names in Parity

Every semantic mesh-bearing glTF node emitted or normalized by Tau must have a non-empty node name and matching mesh name. Line-only helper nodes do not count as semantic shapes and must not consume shape ordinals.

**Why**: Explorer labels, geometry analysis, and GLB inspection tools may read either the node name or mesh name.

CORRECT:

```typescript
await normalizeGltfGeometryNames(bytes, {
  format: 'glb',
  rewriteLegacyGeneratedShapeNames: true,
});
```

INCORRECT:

```typescript
mesh.setName('Mesh');
node.setName('Shape_0');
```

### 4. Leave Tau-Generated Materials Unnamed

Do not assign generated glTF or STEP material names from colors, shape labels, generic fallback strings, or edge/outline roles. Preserve authored/imported material names. Use a generated material name only when it encodes a true semantic role that user-facing tooling should rely on.

**Why**: Material names surface in component appearance metadata and can affect direct-writer material de-duplication; fake labels are not user concepts.

CORRECT:

```typescript
material: {
  baseColorFactor,
  metallicFactor,
  roughnessFactor,
  doubleSided: true,
  alphaMode,
}
```

INCORRECT:

```typescript
material: {
  baseColorFactor,
  name: color ? `rgba(${r},${g},${b},${a})` : 'default',
}
```

### 5. Encode Primitive Semantics Outside Material Names

Express surface, edge, line, face, and topology semantics through glTF primitive mode, extras, extensions, or topology payloads. Do not make material names the source of truth for primitive kind.

**Why**: Different kernels may need multiple visual materials for the same role; role identity belongs in structured metadata.

CORRECT:

```typescript
extras: {
  tauComponentKind: 'line',
  tauComponentSelector: 'node/0/edges',
}
```

INCORRECT:

```typescript
material: {
  name: 'outline-Shape 1';
}
```

### 6. Keep Tau-Generated Single-Scene GLBs Anonymous

Do not name Tau-generated single-scene GLB/glTF documents. Preserve imported/authored scene names. Treat converter fallback names such as `Scene` as generated at non-GLB import boundaries.

**Why**: Scene names are document metadata, not part labels; naming every generated scene `Scene` adds noise without identity.

CORRECT:

```typescript
const scene = document.createScene();
if (importedRootName) scene.setName(importedRootName);
```

INCORRECT:

```typescript
document.createScene(rootName || 'Scene');
```

### 7. Separate Component Display Names From Component IDs

Use human-readable shape labels for component `name` fields. Use payload-local machine addresses for generated component IDs, such as `component:node-0`. Do not derive generated component IDs from display labels, material indices, or mutable UI text.

**Why**: Component IDs power chat references, persisted display state, exports, screenshots, and selection; renaming a part should not silently change generated identity.

CORRECT:

```typescript
const id = formatComponentId(nodeIndex);
const name = shapeDisplayLabel;
```

INCORRECT:

```typescript
const id = `component:${sanitize(displayName)}`;
```

### 8. Treat Selectors as Payload Addresses

Selectors must describe how to locate a component in one geometry payload, not how to display it. Current runtime selectors use forms such as `node/0`, `node/0/surface`, and `node/0/edges`.

**Why**: Selectors are routing addresses for actions; display labels are not stable enough for payload addressing.

CORRECT:

```typescript
const selector = formatNodeSelector(nodeIndex);
const surfaceSelector = formatPrimitiveSelector(nodeIndex, 'surface');
```

INCORRECT:

```typescript
const selector = `part/${displayName}`;
```

### 9. Keep Topology Payload Domains Explicit

In `TAU_cad_topology`, `components[].name` is the display label, `components[].id` is machine identity, `components[].selector` is a payload address, and `nodeIndex` binds the component to glTF node order.

**Why**: Replicad currently defines the richest topology surface; future kernels must not reinterpret those fields.

### 10. Re-Normalize Serialized Native Handles at Boundaries

Serialized native handles may store generated display labels for caching and export. On deserialization or export rebuilds, re-run the same naming helpers used by render output rather than trusting stale or blank names.

**Why**: Cached native handles cross render sessions; generated labels should stay aligned with current output order.

### 11. Include Stable Context in Diagnostics

Diagnostics that mention a component must include the human label plus a stable disambiguator such as part index, selector, component ID, or source name when available.

**Why**: Duplicate labels are allowed; diagnostics need enough context for users and agents to locate the failing geometry.

### 12. Use Artifact Names by Export Intent

Use `model.*` for single-document mesh exports, assembly-style names for BRep assembly exports, and sanitized display labels only for true multi-file per-shape exports. Deduplicate per-shape artifact basenames deterministically.

**Why**: Download filenames describe the export artifact, not necessarily the first shape in the model.

## Decision Tables

### Provenance

| Source                       | Preserve non-empty names?                                                              | Rewrite known generated names? | Fill blanks?      |
| ---------------------------- | -------------------------------------------------------------------------------------- | ------------------------------ | ----------------- |
| Authored user code           | Yes                                                                                    | No                             | Shape labels only |
| User-imported GLB/glTF       | Yes                                                                                    | No                             | Shape labels only |
| Tau-generated runtime output | No for materials/scenes; yes for shape labels through helpers                          | Yes                            | Shape labels      |
| Tau converter output         | Preserve meaningful shape names; clear known generated materials/scenes                | Yes                            | Shape labels      |
| Upstream engine output       | Preserve meaningful names; clear known generated material/scene labels at Tau boundary | Yes when known generated       | Shape labels      |

### Naming Domains

| Domain                  | Target owner                                        | Generated fallback                |
| ----------------------- | --------------------------------------------------- | --------------------------------- |
| Shape display label     | `shape-names.ts`                                    | `Shape N`                         |
| glTF node/mesh name     | Direct writer or `gltf-geometry-name-normalizer.ts` | `Shape N` for semantic mesh nodes |
| Material name           | Authored/imported data only                         | Omitted                           |
| Scene name              | Authored/imported data only                         | Omitted                           |
| Component ID            | Geometry naming helper or topology producer         | `component:node-N`                |
| Selector                | Geometry naming helper or topology producer         | `node/N`                          |
| Single-file mesh export | Kernel export boundary                              | `model.<ext>`                     |
| BRep assembly export    | Kernel export boundary                              | `assembly` or `assembly.<ext>`    |
| Per-shape export        | Kernel export boundary                              | sanitized display label           |

## Anti-Patterns

- `AnyShape`, `Geometry`, `Mesh`, or `Shape_0` as Tau-owned generated part labels
- `default`, raw color strings, `rgba(...)`, `outline-*`, or shape labels as Tau-owned material names
- `Material_Default` / `Material_*` as converter-authored material names
- `Scene` as a Tau-generated single-scene fallback
- `component:${displayName}` as a generated component ID
- component IDs that include material indices

## Summary Checklist

- [ ] Authored/imported names are preserved by provenance.
- [ ] Generated shape labels come from `shape-names.ts`.
- [ ] Semantic glTF node and mesh names are non-empty and equal.
- [ ] Tau-generated materials and single scenes are unnamed.
- [ ] Primitive semantics live in modes, extras, or topology payloads.
- [ ] Component IDs and selectors are payload addresses, not labels.
- [ ] Diagnostics include labels plus disambiguating context.
- [ ] Export artifact names follow single-document, assembly, or per-shape intent.
- [ ] Tests parse GLB/glTF with `NodeIO` and assert observable names.
