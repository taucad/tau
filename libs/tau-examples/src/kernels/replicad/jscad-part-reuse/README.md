# JSCAD insert reuse

`upstream.ts` authors an independent mesh insert. `main.ts` imports its exported immutable STL as a Replicad MeshShape and adds an editable mounting plate. `upstream.settings.ts` changes the producer geometry; `downstream.settings.ts` changes only the plate. Imported mesh geometry remains display-only and cannot establish exact BRep or measured native-solid volume.

The runtime regression `apps/runtime-e2e/src/parts-assemblies-reuse.test.ts` uses the public publication/export/opening workflow: produce and pin the upstream part, export STL (existing JSCAD GLB → Assimp STL route), write its digest-named dependency `assets.d.ts`, and `upstream-asset.ts`, and publish the downstream scene with the upstream record pin. It checks downstream-only edits in warm and fresh sessions, upstream producer and mesh call counts, stable upstream digests, changed-input controls and source-free portable reopening.

Authored sources are original Tau Apache-2.0 examples. The packaged STL and asset import are generated from this producer; regenerate them only after the producer-input control passes.

To regenerate after editing the producer, run `pnpm nx run runtime-e2e:test -- src/parts-assemblies-reuse.test.ts --watch=false --maxWorkers=1`. After both unchanged-input checks and the changed-input control pass, copy `assets/`, `roots/`, `assembly.json`, `scene.json`, `producer.json`, `assets.d.ts`, and `upstream-asset.ts` from `out/research/parts-assemblies-execution/2026-09-30/s08-runtime/mixed/jscad/` into this directory. `producer.json` in that output records the producer source hashes and exported STL/GLB digests. The final packaged-closure check may report a stale fixture after a producer edit; the verified output is already emitted. Copy that output, then rerun the test to verify the new packaged closure. The mounting plate can be edited independently without regenerating this dependency.

`main.ts` is the ordinary CAD model entry. `assembly.json` is the editable authored assembly: it keeps the upstream occurrence pinned independently and evaluates `main.ts` for the downstream occurrence. Publish it through `RuntimeClient.publishAssembly`; pass the resulting root to the approved `openAssembly` facade with the existing shared CAD admission adapter. `scene.json` is the pinned generation pointer for separate upstream and mounting-plate occurrences. Its immutable manifest and ordered chunks under `roots/sha256/` contain the logical scene; the record/GLB closure remains under `assets/`. Open `scene.json` in the editor and choose **Open in Viewer** for the existing product admission route. Opening the verified complete closure does not evaluate source. The regression emits both the original `scene/scene.json` lane closure and this packaged root with its relocated record paths.

The upstream record lives under `assets/parts/sha256/` so the repository formatter preserves its digest-constrained JSON bytes. Its pin uses that root-relative path; the record digest and GLB digest remain unchanged.
