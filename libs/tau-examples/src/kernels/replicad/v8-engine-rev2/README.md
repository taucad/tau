# v8-engine-rev2 — TDD-red GeoSpec suite

Red-first verification contract for the rev2 production-fidelity V8, transcribed
verbatim from `docs/research/v8-engine-rev2-sysml2-specification.md` (121
requirements, REQ-V8R2-001..121). **No CAD model exists yet**: every
model-loading test fails until a follow-up implements the exports below. That
red baseline is deliberate — do not "fix" these tests by weakening them.

## Run

```bash
pnpm exec tsx packages/geospec/src/cli.ts run libs/tau-examples/src/kernels/replicad/v8-engine-rev2 --test-timeout 300000
```

Expected today: the pure-TS registry/suite-lint tests pass (deferral registry,
census transcription, contract hygiene); all model-loading tests fail with
missing-export diagnostics. This project is intentionally **not** registered in
`libs/tau-examples/src/manifest.ts` until the model lands.

## Verification classes (spec Section 1.3 / 6.1)

- **85 verify-today REQs** — executable tests across the nine suite files,
  including the 7 landed void-continuity flow-path REQs.
- **26 frontier-gated REQs** — documented deferrals in `spec/deferrals.ts`
  (REQ id + frontier + gate + quantified criterion held in reserve). Each
  cluster file asserts its own deferrals are registered; a frontier landing
  converts its entries to red tests in the same change. Never fake-pass these.
- **10 process-only REQs** — review-checklist registry; three (101/102/104)
  also run as pure-TS suite lints over the contract data in
  `geospec/census.geospec.ts`.

### Occurrence naming (spec Section 1.5, enforced bidirectionally)

`<Part> <n>` with global 1-based ordinals; bank singletons `<Part> R` /
`<Part> L`. Cylinders: right bank 1–4 front→rear, left bank 5–8. Valves
v = 2c−1 (intake) / 2c (exhaust); keepers k = 2v−1, 2v; main cap k holds
bolts 2k−1, 2k; rod c holds bolts 2c−1, 2c; head bolts 1–10 = bank R,
11–20 = bank L; circlips 2c−1 (front boss) / 2c. The full 650-name census
lives in `spec/census.ts` — the export inventory must equal it exactly, both
directions (REQ-V8R2-100).

## Deferral policy

`spec/deferrals.ts` is the single registry. Rules: (1) a frontier-gated REQ
never gets a geometry test before its frontier lands; (2) when a frontier
lands, its deferral entries convert to red tests in the same change; (3) the
registry tallies must keep matching Section 6.1 (9 rev2.1 + 6 rev2.1+ +
11 rev2.2 by frontier; 10 process-only) — `deferred-frontiers.geospec.ts`
enforces this and
the 85/85 executable coverage of the verify-today set.
