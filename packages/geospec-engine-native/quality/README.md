# Critical coverage acceptance (A1-R7)

`gate.py` consumes retained coverage artifacts. It never compiles, imports or runs
GeoSpec. `test_gate.py` exercises only small synthetic coverage documents and the
gate's file/provenance checks. Python's standard library is the only dependency.

The current inventory is **prospective, not qualified**. It pins current source
bytes, critical files and owned vendor function spans, target/feature profiles and
every other package file. No real coverage or compiler instrumentation map was
produced during S10's execution hold. A missing map, report, metric, instrumenter
pin or generated-source correspondence fails closed. Synthetic counts are never
used to qualify product source.

## Denominator and approval

The owning contract is `docs/research/geospec-native-quality-security-research.md`
Finding 2 and charter A1-R7. Inventory scope is **all files in this native package**,
including ignored/new source. SDK `packages/geospec` and retained-engine coverage
remain separate package gates; this gate does not certify them. In particular it
does not perpetuate their broad `types.ts` exclusion. Native `src/host-types.ts`
contains executable error handling and is critical.

`inventory.json` is a checked-in review object, not generated from coverage results.
First-party critical scope includes every executable line, function and
instrumentable branch in its pinned target configuration. Statements are also
required when supplied by Istanbul. LLVM regions do not add a zero-region-miss rule.

For the five modified Manifold files, `critical_spans` selects **21 changed or new
functions and four added source items**, not the whole upstream files. The spans
run from each function declaration through its closing brace, including nested
helpers and closures. `vendor-ownership.json` and `vendor-owned.patch` provide the
pinned upstream blob/file hashes, complete diff, span hashes and explicit test,
non-executable and formatting-only dispositions. Unchanged behavior remains vendor
conformance scope. The LCOV map for each such file stays complete: omitted upstream
coordinates still fail map validation, while only owned coordinates have a 100%
threshold. Function spans without line/function mapping fail; derived-item coordinates
are critical whenever emitted. Approving a baseline also requires checking generated
function/source correspondence. No regex navigation or guessed branch maps are kept.

Before the first acceptance run, the Principal must approve the source classification
and exact per-profile instrumentation map. Export a complete zero-count/initial
map from the actual instrumented build using the same standard format as its
eventual report; preserve every executable coordinate, including unexecuted files.
Set the profile's `baseline` to `{ "path": "...", "sha256": "..." }`, pin the
instrumenter and build configuration, and review any truly empty file/metric in
`empty_metrics` by exact source path and metric. No unsupported branch metric may
be described as a branchless file. Source declarations, compiler-generated code,
target-disabled code and embedded `cfg(test)` modules need explicit correspondence
in that review. Exporters must retain all production code, not only loaded files.
The gate compares the **exact** file, metric and coordinate sets against that map.
It cannot prove the completeness of a map a reviewer incorrectly approves.

Pin the resulting inventory SHA-256 in Principal-controlled CI configuration, not
by hashing the candidate manifest during CI. Changing source, exclusions, profiles
or baseline hashes then invalidates approval. There is no `--update`, learn-from-hit
report, threshold override or result-driven regeneration mode. Prospective source
changes require a new review before their results are used. Do not shrink a red
denominator. The lane's initial inventory snapshot preserves this attempt's scope.

Generated shipped Node/Emscripten glue and built output are not claimed covered
by source coverage. The explicit `generated_equivalence` rows currently block
qualification until the Principal pins a reviewed mapping/equivalence artifact
with generator versions, source hashes, generated bytes and boundary checks.
Raw addon/wheel/browser product hashes accompany each profile receipt. The gate
checks their bytes, not whether a caller really executed them; that remains the
trusted collection job and independent receipt review's responsibility.

## Formats and target separation

- `lcov`: classic LLVM `SF/FN/FNDA/DA/BRDA` records with all six line/function/branch
  found/hit summaries. Missing summaries, duplicate records or inconsistent counts
  fail. Merge compatible shards with the instrumenter's merge tool before export.
  Remap paths to repository-relative paths. Reuse across functional hosts requires
  the separately pinned cohort correspondence described below; do not merge
  incompatible targets, features, instrumentation maps or build contexts.
- `istanbul`: source-mapped `coverage-final.json`, including exact statement,
  function and branch location maps/counts. Line counts follow statement-start
  line semantics. Skip coordinates and mismatched map/count keys fail.
- `coveragepy`: coverage.py JSON format 3 with functions and branch coverage.
  Executed/missing lines and arcs are combined into a full map; excluded lines fail.
  Function execution uses that function's executed lines. JSON format 2 and line-only
  data cannot qualify Python functions/branches. No installed coverage.py was found
  during preparation, so that producer version remains explicitly unpinned.

The release matrix is nine functional boundaries: native Node 24/26, mixed
Node 24/26, CPython 3.13/3.14, and mixed Chromium/Firefox/WebKit. The retired
core-only wasm-bindgen prototype remains inventoried as `unshipped`; current
package imports and tsdown copies contain no `#wasm-binding`. Its source and old
generated output impose no release runtime coverage requirement.

Coverage configurations are not a Cartesian product of that matrix. Native Node's
Rust/C++ profiles are prospective cohorts for the same NAPI binary on Node 24/26;
mixed Rust/C++ profiles are prospective cohorts for the same Wasm binary across
both Node versions and all three browsers. Every functional boundary remains in
`release_boundaries` and its profiles' `boundaries`. JS coverage stays host-specific;
Python ABIs stay separate. Selected Cargo features and build-script profiles remain
explicit. No automatic merging or equivalence inference is implemented.

A profile spanning multiple boundaries cannot qualify while `cohort_correspondence`
is null. Principal must first pin a review artifact proving the identical instrumented
binary, target/features/build context and complete maps, plus compatible collection
and source correspondence. Its receipt must reference that same artifact and include
hashed `boundary_receipts` for **every** listed functional host. Single-boundary
profiles also retain their functional receipt. These hashes preserve evidence joins;
independent receipt review establishes what really executed. If no cohort can be
proved, split that configuration prospectively before accepting results. This is
not permission to skip a host's functional checks or weaken a critical metric.

Rust stable branch instrumentation and Wasm mapping availability must be demonstrated
with exact toolchain evidence; missing metrics remain not qualified. An alternative
assurance route needs a separately approved disposition, not fictional counters.
Broader platforms are not certified by this bounded current-target inventory.

Noncritical owned executable code also needs a map and actual report. Its misses
are reported without a new 100% threshold. Test/harness sources, fixtures, declarations,
configuration and unchanged vendor files have individual reasons/hashes. Artifact
directories are exact paths, not filename patterns that can hide `types.ts`.

## Receipt and invocation

The receipt JSON shape is:

```json
{
  "inventory_sha256": "<Principal-approved digest>",
  "profiles": {
    "<exact profile id>": {
      "configuration": { "copy": "the exact profile.configuration object" },
      "instrumenter": { "copy": "the exact profile.instrumenter object" },
      "boundary": "<exact profile.boundary coverage scope label>",
      "boundary_receipts": {
        "<each listed profile.boundaries entry>": { "path": "out/...", "sha256": "<hash>" }
      },
      "cohort_correspondence": { "path": "<approved review, for multi-boundary profiles>", "sha256": "<hash>" },
      "products": [{ "path": "out/artifacts/...", "sha256": "<actual hash>" }],
      "coverage": { "path": "out/reports/coverage/...", "sha256": "<actual hash>" }
    }
  }
}
```

Paths are repository-relative. Coverage source paths can also be absolute under
the current checkout; remap foreign checkout paths at export. Receipts bind to the
entire inventory digest. Context should pin resolved dependencies, compiler flags,
profile/environment and build products when the baseline is reviewed. Human labels
are not proof of those settings. Missing receipt files produce JSON `not-qualified`
and exit 1; successful qualification exits 0. Output contains actual metric totals,
hits and missing coordinates, not rounded percentages.

From the workspace root:

```sh
python3 -B packages/geospec-engine-native/quality/test_gate.py
python3 -B packages/geospec-engine-native/quality/gate.py \
  --inventory-sha256 "$GEOSPEC_COVERAGE_INVENTORY_SHA256" \
  --receipts out/reports/coverage/packages/geospec-engine-native/receipts.json
```

`nx-targets.proposed.json` contains the exact two targets for Principal to add to
the existing `geospec-engine-native` project. No nested project/package is needed.
Both are uncached; changing externally produced artifacts must not reuse a prior
green result. Principal should add the static check to normal CI now. Add the gate
after artifact download, with a protected digest and `if: always()` artifact upload:

```yaml
- name: Check coverage gate implementation
  run: pnpm nx run geospec-engine-native:check-coverage-gate
- name: Accept retained coverage
  env:
    GEOSPEC_COVERAGE_INVENTORY_SHA256: ${{ vars.GEOSPEC_COVERAGE_INVENTORY_SHA256 }}
  run: |
    set -o pipefail
    mkdir -p out/reports/coverage/packages/geospec-engine-native
    pnpm nx run geospec-engine-native:coverage-critical --output-style=stream \
      | tee out/reports/coverage/packages/geospec-engine-native/gate.log
- uses: actions/upload-artifact@v4
  if: always()
  with:
    name: geospec-native-critical-coverage
    path: out/reports/coverage/packages/geospec-engine-native/
```

The collection jobs are deliberately not invoked here. Missing data makes this
acceptance job red. Keep the S10 execution hold on all native/fault/fuzz/sanitizer/
malformed/lifetime suites until the Principal separately lifts it. This gate does
not replace Clippy, security qualification or boundary behavior checks.
