## Project notes

Record durable project-specific facts here after verifying them in current source.

- The native handle is `@tscircuit/core`'s settled circuit JSON and the GLB comes from `circuit-json-to-gltf`; a catalog bump of either package changes cached handle semantics, so bump the kernel `version` alongside it.
- Rendering is offline by default: `withOfflineFetch` traps `globalThis.fetch` around circuit settling and 3D conversion and reports each attempted URL as a warning issue. The kernel's `parts: 'online'` option lets only the https hosts in `onlinePartHosts` through; the guard serves `tau-models:` URLs from the local KiCad pack.
- The KiCad pack (lookups in `src/kicad-pack.ts`, the entry catalogue in `src/engine/kicad-catalog.ts` so it loads lazily with the engine, assets in `src/assets/kicad/`) is generated by `node build-kicad-pack.ts` from the package root. Pack GLBs keep KiCad's Z-up millimetre frame and use separate vertex buffers, because circuit-json-to-gltf maps GLB axes like STEP and ignores `byteStride`. Bump `kicadPackVersion` when entries or tessellation change. Entries list the footprinter strings (with an `ftype` when the string is shared, like `0603` for LEDs and inductors) whose pads the KiCad footprint matches, and `footprinterRotation` when the KiCad model runs along another axis; `kicad-pack.test.ts` fails a mapping whose pads land more than 0.5 mm apart. Lookups drop parameters that never change the part (`footprinterCandidates`); mapped models sit on their KiCad pad centre (`loadPackPadCentre`), as KiCad's origin is often pin 1. Modelless parts (inline `<footprint>`) get a courtyard box from `src/engine/generic-body.ts`.
- The converter never rasterizes a board texture (`boardTextureResolution: 0` on every path), so the engine stubs its svg-to-png chunk and ships no resvg.
